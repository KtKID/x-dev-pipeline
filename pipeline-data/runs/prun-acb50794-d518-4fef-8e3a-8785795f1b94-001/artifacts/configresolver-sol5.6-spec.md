# 多来源配置解析器 模型 sol5.6极高

## 任务目标

- 在 module 根目录提供名称与签名完全符合任务契约的 `configresolver` Go 包及公开 API。
- `Resolve` 按来源优先级完成标量覆盖、对象递归合并、数组整体替换和 `nil` 删除，并返回最终配置及逐叶子来源。
- 所有来源在合并前接受完整 Schema 校验，未知字段、类型错误和必填字段删除或缺失可通过指定哨兵错误被 `errors.Is` 识别。
- 解析过程保持全部输入对象不变；相同输入结果确定；共享同一 `sources` 的并发调用无数据竞争。
- 约 100 个字段的配置连续解析 10,000 次总耗时低于 2 秒，且 `go test ./...`、`go vet ./...` 通过。

## 非目标

- 不负责从文件、环境变量、命令行、网络、数据库或 UI 读取配置。
- 不提供 JSON/YAML 等序列化与反序列化能力。
- 不合并数组元素，也不校验数组元素类型。
- 不提供类型转换、默认值注入、自定义字段类型或 Schema 扩展语法。
- 不增加任务契约之外的公开 API。

## 影响边界与不变量

| 模块 | 角色 | 本次影响 | 必须保持的不变量 | 依据 |
|---|---|---|---|---|
| `Go 调用方` | 上游 | 传入 Schema 与按低到高优先级排列的来源，可并发复用同一输入 | 调用前后的 Schema、`sources`、各层 map/slice 与 `nil Data` 完全一致 | `J2`、`J9`、`J10` |
| `configresolver 公开契约` | 目标 | 新建 module、导出类型、错误变量和 `Resolve` | module 名、包位置、名称、字段和函数签名与任务 API 完全一致；错误支持 `errors.Is` | `J1` |
| `来源验证器` | 目标 | 逐来源递归检查字段存在性、合法类型及 Schema 类型 | 每个来源独立校验；低优先级错误不会被后续覆盖掩盖；校验顺序确定 | `J3`、`J5`、`J6`、`J8` |
| `递归合并器` | 目标 | 维护字段存在、删除屏障与高优先级覆盖状态 | 对象递归合并；数组整体替换；`nil` 清除已有子树；必填约束覆盖完整 Schema 树 | `J2`、`J4` |
| `Provenance 生成器` | 目标 | 为最终叶子值记录最后生效来源 | 键为正确转义的 JSON Pointer；配置键保持原名；删除同步清除子树来源 | `J7` |
| `Resolve 结果消费者` | 下游 | 消费 `Result.Config`、`Result.Provenance` 与哨兵错误 | 最终值、来源和错误类别可观察且稳定；结果中不出现已删除字段 | `J1`、`J7`、`J8` |
| `Go 测试与工具链` | 相关 | 编译、单测、竞态、静态检查与性能验收 | 标准库实现；全部交付命令通过；性能阈值可复现验证 | `J10` |

## 验收清单

### 单元测试

- [ ] 标量覆盖、对象递归合并、数组整体替换及对象删除屏障符合低到高优先级语义。
- [ ] 可选删除、必填显式删除、根级与嵌套必填全局缺失均得到准确字段状态和错误类别。
- [ ] 未知字段与类型错误覆盖根级、嵌套、低优先级且随后被覆盖的来源。
- [ ] 五类 Schema 类型的有效值与无效值均被表驱动测试覆盖。
- [ ] Provenance 覆盖混合来源、删除、数组叶子及包含 `~`、`/` 的字段名。
- [ ] 成功、错误与 `nil Data` 路径均通过输入深度快照证明零修改。
- [ ] 重复解析的结果、来源、首个错误路径与错误文本保持一致。

### Smoke 测试

- [ ] 外部测试包只通过公开 API 构造最小多来源配置，`go test ./...` 完成编译和行为验证。
- [ ] `go test -race ./...` 覆盖多个 goroutine 共享同一 Schema 和 `sources` 的调用并得到一致结果。
- [ ] 100 字段配置连续 `Resolve` 10,000 次总耗时低于 2 秒。
- [ ] `go vet ./...` 通过。

### E2E 测试

- 决策：省略
- 依据：交付物是无网络、数据库、UI 和跨进程依赖的单一 Go 库；公开包 Smoke、竞态测试与性能测试覆盖完整真实调用边界。

## 测试驱动开发

1. 公开模块与 API 契约可编译 → 先写外部包编译测试。
2. 高优先级覆盖普通字段、对象递归合并、数组整体替换 → 先写三组核心合并测试。
3. 对象删除形成合并屏障、可选字段删除并清除来源 → 先写删除状态与来源清理测试。
4. 必填字段显式删除报错、嵌套必填字段全局缺失报错 → 先写根级与嵌套必填测试。
5. 任意来源的未知字段报错、被覆盖来源的类型错误仍报错、五类字段按契约校验 → 先写递归表驱动校验测试。
6. 叶子来源与 JSON Pointer 转义准确 → 先写混合来源、数组及特殊字段名测试。
7. 输入在成功和失败路径保持不变 → 先写输入深度快照测试。
8. 相同输入的结果与错误确定 → 先写高频重复调用测试。
9. 共享输入并发解析无竞态 → 先写并发一致性测试并用竞态检测器运行。
10. 百字段万次解析低于两秒 → 先写性能门槛测试。
11. 标准交付命令通过 → 实现满足前述测试的最小代码，重构后复跑全部 Smoke 命令。

## Scenarios

### Scenario: 公开模块与 API 契约可编译

- **GIVEN** module 根目录和一个只导入 `configresolver` 公开符号的外部测试包
- **WHEN** 执行 `go test ./...`
- **THEN** `go.mod` 首行为 `module configresolver`，根目录包为 `configresolver`，指定类型、字段、错误变量与 `Resolve` 签名全部编译成功
- 测试层：smoke
- 依据：`J1`

### Scenario: 高优先级覆盖普通字段

- **GIVEN** 多个来源按低到高排列，并为同一标量字段提供类型合法的不同值
- **WHEN** 调用 `Resolve`
- **THEN** 最终配置保留最高优先级值，且该叶子的 Provenance 为最高优先级来源名
- 测试层：unit
- 依据：`J2`

### Scenario: 对象递归合并

- **GIVEN** 不同优先级来源为同一对象提供互补子字段，并对其中一个叶子重复赋值
- **WHEN** 调用 `Resolve`
- **THEN** 对象保留互补叶子，重复叶子采用最高优先级值，每个叶子记录各自最后生效的来源
- 测试层：unit
- 依据：`J2`、`J7`

### Scenario: 数组整体替换

- **GIVEN** 低优先级来源提供一个数组，高优先级来源为同一字段提供另一个数组
- **WHEN** 调用 `Resolve`
- **THEN** 最终配置只包含高优先级数组的完整内容，Provenance 在数组字段路径记录高优先级来源
- 测试层：unit
- 依据：`J2`、`J7`

### Scenario: 对象删除形成合并屏障

- **GIVEN** 低优先级来源建立含多个叶子的对象，中间来源以 `nil` 删除该对象，更高优先级来源只重建一个子字段
- **WHEN** 调用 `Resolve`
- **THEN** 最终对象只包含删除后重建的子字段，删除前的叶子与 Provenance 均不再出现
- 测试层：unit
- 依据：`J2`

### Scenario: 可选字段删除并清除来源

- **GIVEN** 低优先级来源设置可选标量或对象字段，高优先级来源为该字段提供 `nil`
- **WHEN** 调用 `Resolve`
- **THEN** 最终配置移除该字段及其全部后代，Provenance 移除对应路径及后代路径
- 测试层：unit
- 依据：`J2`、`J7`

### Scenario: 必填字段显式删除报错

- **GIVEN** Schema 将字段标为必填，任一来源对该字段提供 `nil`
- **WHEN** 调用 `Resolve`
- **THEN** 返回可由 `errors.Is` 识别为 `ErrRequiredRemoved` 的错误
- 测试层：unit
- 依据：`J4`

### Scenario: 嵌套必填字段全局缺失报错

- **GIVEN** Schema 的根级或对象 `Children` 中存在必填字段，所有来源均未提供该字段，嵌套字段的父对象也可能完全缺失
- **WHEN** 调用 `Resolve`
- **THEN** 返回可由 `errors.Is` 识别为 `ErrRequiredRemoved` 的错误，并稳定标识缺失字段路径
- 测试层：unit
- 依据：`J4`、`J8`

### Scenario: 任意来源的未知字段报错

- **GIVEN** 任一来源在根级或对象内部包含 Schema 未声明的字段，该字段随后可能被删除或被更高优先级来源覆盖
- **WHEN** 调用 `Resolve`
- **THEN** 返回可由 `errors.Is` 识别为 `ErrUnknownField` 的错误，并稳定标识来源和字段路径
- 测试层：unit
- 依据：`J3`、`J8`

### Scenario: 被覆盖来源的类型错误仍报错

- **GIVEN** 低优先级来源包含类型不匹配的标量或对象子字段，高优先级来源为同一路径提供合法值
- **WHEN** 调用 `Resolve`
- **THEN** 返回可由 `errors.Is` 识别为 `ErrTypeMismatch` 的错误，低优先级错误不会被覆盖掩盖
- 测试层：unit
- 依据：`J3`

### Scenario: 五类字段按契约校验

- **GIVEN** 表驱动输入覆盖 `string`、所有整数与浮点 kind、`boolean`、`map[string]any` 对象和 `[]any` 数组及各自反例
- **WHEN** 分别调用 `Resolve`
- **THEN** 合法值成功解析，对象递归检查 Children，数组元素保持原值，无效值返回可由 `errors.Is` 识别为 `ErrTypeMismatch` 的错误
- 测试层：unit
- 依据：`J5`、`J6`

### Scenario: 叶子来源与 JSON Pointer 转义准确

- **GIVEN** 多来源嵌套对象、数组叶子和字段名中同时包含 `~` 与 `/`
- **WHEN** 调用 `Resolve`
- **THEN** Config 保留原始字段名，Provenance 只含最终叶子，路径段按 RFC 6901 转义并映射到最后生效来源
- 测试层：unit
- 依据：`J7`

### Scenario: 输入在成功和失败路径保持不变

- **GIVEN** 含嵌套 map、slice、`nil Data` 的 Schema 与来源深度快照，以及一组会触发校验错误的来源
- **WHEN** 分别调用成功和失败的 `Resolve`
- **THEN** 所有输入与调用前深度相等，原本为 `nil` 的 `Source.Data` 仍为 `nil`
- 测试层：unit
- 依据：`J9`

### Scenario: 相同输入的结果与错误确定

- **GIVEN** map 插入顺序不同但内容相同的有效输入与包含多个错误候选的无效输入
- **WHEN** 对每组输入重复调用 `Resolve`
- **THEN** 有效调用的 Config 与 Provenance 始终深度相等，无效调用的错误类别、路径和文本始终一致
- 测试层：unit
- 依据：`J8`

### Scenario: 共享输入并发解析无竞态

- **GIVEN** 多个 goroutine 共享同一 Schema 和 `sources` 切片并保存一份期望结果
- **WHEN** 在 `go test -race ./...` 下并发调用 `Resolve`
- **THEN** 每次调用都得到与期望值深度相等的结果，竞态检测器无报告，输入保持不变
- 测试层：smoke
- 依据：`J9`、`J10`

### Scenario: 百字段万次解析低于两秒

- **GIVEN** 约 100 个字段的 Schema 与有效多来源配置
- **WHEN** 连续调用 `Resolve` 10,000 次并测量总耗时
- **THEN** 总耗时严格小于 2 秒且每次调用返回成功
- 测试层：smoke
- 依据：`J10`

### Scenario: 标准交付命令通过

- **GIVEN** 完整实现与必要测试均位于 module 内
- **WHEN** 依次执行 `go test ./...` 和 `go vet ./...`
- **THEN** 两条命令退出码均为 0，代码只依赖 Go 标准库
- 测试层：smoke
- 依据：`J1`、`J10`
