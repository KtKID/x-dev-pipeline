# 编辑器连接本地 DeepSeek 助手

让支持编辑器通过本机启动的 DeepSeek 助手开展对话，及时看到回复和工具进度，并在需要时中止或恢复会话。

## 本次目标与完成条件

- 本次目标与范围：交付单编辑器进程、单会话的本地入口，支持创建和恢复会话、文本对话、回复与工具状态更新、取消及断开清理。
- 验证证据：通过本地离线助手检查会话创建与恢复、输入校验、更新顺序、工具成功和失败、输出上限、模型失败、取消和断开回收，并确认协议输出可由编辑器逐行读取。
- 完成条件：本 spec 的全部场景在给定离线环境中满足预期，已有会话记录可恢复并继续对话；交付可复跑测试和阶段产物，并记录未覆盖范围。

## feat01: 创建和恢复会话

编辑器可以在本地助手中创建一个会话，或在进程重启后接续已有会话。

场景1: 创建本地会话
必要性：用户要求编辑器创建会话、入口无需身份验证且只支持文本内容；缺少时编辑器无法开始本地对话。
- GIVEN 编辑器以启动目录连接本地助手
- WHEN 编辑器完成初始化并创建会话
- THEN 助手确认使用版本 1，返回会话标识并声明可恢复会话、接受文本内容，且不要求用户登录

场景2: 拒绝越界或冲突的会话请求
必要性：用户要求启动目录绝对路径、空额外服务列表和单会话限制；缺少时入口会越过工作目录边界或同时管理多个会话。
- GIVEN 首次创建或恢复请求指定未知会话、非启动目录或非绝对工作目录，或携带非空额外服务列表；或两个有效创建/恢复操作仍未完成；或当前进程已持有会话
- WHEN 编辑器提交首次无效操作、在首个有效操作完成前提交第二个有效操作，或在已持有会话时再次创建或恢复
- THEN 无效目录或未知会话的首次操作返回请求错误且不占用会话；重叠的第二个操作被拒绝且首个操作可以完成；已持有会话时的新操作被拒绝且原会话保持不变

场景3: 重启后恢复历史并继续
必要性：用户要求通过同一标识恢复已保存会话并继续；缺少时重启会丢失对话连续性。
- GIVEN 一个会话已正常完成并保存在本地
- WHEN 编辑器在新进程中用同一标识恢复会话
- THEN 助手先按历史顺序回放用户和助手更新，再确认恢复成功，且编辑器可以继续提问

## feat02: 发送文本并接收助手更新

编辑器可以提交文本、查看助手回复与工具进度，并区分不同结束结果。

场景1: 展示按序处理的回复和工具进度
必要性：用户要求非空文本按原顺序交给助手、实时显示正文与公开思考，并用同一调用标识展示工具状态；缺少时编辑器无法准确呈现一次有效对话。
- GIVEN 编辑器提交一组非空文本块，助手产生正文、公开思考或工具调用
- WHEN 助手处理请求并产生更新
- THEN 文本按提交顺序处理；正文在生成过程中分段到达并实时显示，思考独立显示；工具开始及成功或失败状态使用同一调用标识，且应有更新先于请求结算

场景2: 原子拒绝无效输入
必要性：用户要求空提示、混入非文本内容和未知会话均返回请求错误，且拒绝请求不提交部分输入；缺少时无效内容会污染会话。
- GIVEN 编辑器提交空提示、混合文本与非文本内容，或使用未知会话
- WHEN 助手校验请求
- THEN 助手返回请求错误，且会话中没有该请求的任何部分输入

场景3: 拒绝同一会话的并发请求
必要性：用户要求同一会话只接受一个未完成请求；缺少时并发输入会让助手回复无法对应到编辑器请求。
- GIVEN 一个会话正在处理请求
- WHEN 编辑器向同一会话再次提交请求
- THEN 助手拒绝第二个请求，且第一个请求继续正常处理

场景4: 区分完成、输出上限与模型失败
必要性：用户要求正常结束、达到输出上限和模型失败分别结算；缺少时编辑器无法区分完整回复、受限回复和失败。
- GIVEN 助手正常完成、达到输出上限或遇到模型失败
- WHEN 助手结束当前请求
- THEN 前两种情况分别返回正常结束或输出受限结果，模型失败返回请求错误，并且此前产生的更新先到达

## feat03: 取消和释放正在运行的工作

编辑器可以取消正在处理的请求，并在连接关闭时释放对应工作。

场景1: 取消正在运行的请求
必要性：用户要求取消通知中止底层工作，且原请求只结算一次；缺少时编辑器无法及时停止正在运行的任务。
- GIVEN 一个会话正在处理请求
- WHEN 编辑器取消该会话
- THEN 助手中止底层工作，原请求以取消结果结算一次，且取消后的请求更新不会越过结算结果

场景2: 空闲取消与后续提问
必要性：用户要求未知或空闲会话的取消不影响正常请求，且取消结束后可以继续提问；缺少时空操作可能破坏会话可用性。
- GIVEN 会话当前空闲，或取消请求指向未知会话
- WHEN 编辑器发送取消通知，随后对有效会话继续提问
- THEN 空闲或未知会话取消不干扰有效会话，后续提问可以正常处理

场景3: 断开连接时清理工作
必要性：用户要求客户端断开后回收正在运行的工作；缺少时编辑器退出会留下无人管理的任务。
- GIVEN 编辑器连接断开时助手仍在处理请求
- WHEN 助手检测到连接关闭
- THEN 助手取消并释放该请求的底层工作
