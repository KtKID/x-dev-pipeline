## 问题详情

### B1: 累计报告会重复降级已经修复并签字的任务
**来源**: spec 对照 + 当前报告结构
**文件**: `dev-pipeline/tasks/progress-engine/plan.md`
**位置**: 第 70-84 行
**严重程度**: P0
**根因分类**: 原始 spec 不一致
**置信度**: 已确认

**问题描述**：
plan 要求读取最新报告的全部 issue 行。当前 qa-gate 报告是累计台账，并粘贴每一轮 mini-report；修复前的 P0/P1 会永久保留在最新文件中。主 agent 在最终 pass 后手动升回 `[x]`，再次运行 progress 仍会读取旧 issue 并重新降级，导致主 agent 的签字无法稳定保存。

**反证检查**：
plan 第 83-84 行假设“新报告不再点名”，当前模板第 18-36 行明确保留累计台账与各轮 mini-report；同步清单只要求格式样例对齐，没有重定义机器消费区和历史区。

**修复建议**：
给报告增加唯一的机器消费块，只列“当前仍有效的 issues”；progress 只解析该块。历史台账与 mini-report 继续保留，但退出解析域。clean pass 的机器块为空，主 agent 升钩后重复运行保持不变。

### B2: 未知 T# 被当作成功
**来源**: 核心目标 + 算法与 DoD
**文件**: `dev-pipeline/tasks/progress-engine/plan.md`
**位置**: 第 29-35、73-79、110 行
**严重程度**: P1
**根因分类**: 原始 spec 不一致
**置信度**: 高

**问题描述**：
报告点名 T9 且 checklist 无 T9 时，命令 warning 后 exit 0。调用方会得到成功结果，坏消息没有落到任何任务行。

**修复建议**：
将 P0/P1 引用未知 T# 定义为契约错误：exit 2，checklist 零写入。P2 引用未知 T# 采用相同完整性校验，避免登记无归属问题。

### B3: reviewer 输出契约未覆盖实际生产文件
**来源**: 当前调用链
**文件**: `skills/x-qa-gate/references/*.md`
**位置**: 各文件输出段
**严重程度**: P1
**根因分类**: 实现过程偏移
**置信度**: 高

**问题描述**：
plan 第 42 行要求 reviewer issue 必须带 Tn。当前 `rc-unified.md` 的固定表格列和 R1/R2/R3 输出要求均无 Tn，plan 的同步清单只列父 SKILL 与聚合报告模板。按当前范围实现后，reviewer 仍可合法产出 progress 无法消费的 issue。

**修复建议**：
把四份 reviewer reference 纳入 Commit B；若 fixes-and-metrics 先完成，则更新合并后的 `reviewer-lenses.md`。另一个轻量方案是明确 T# 由主 agent 聚合时映射，并把该映射失败设为报告生成失败。

### B4: 重复 T# 令“对应行”失去唯一性
**来源**: checklist 数据边界
**文件**: `tools/xdev.py`
**位置**: 第 506-525 行
**严重程度**: P1
**根因分类**: spec 缺口
**置信度**: 高

**问题描述**：
当前 V9 用 set 收集 known IDs，没有报告重复 T#。progress 方案也未定义重复 ID 时更新首行、全部行或失败，核心映射无法保持唯一。

**修复建议**：
在 progress 解析阶段拒绝空任务表和重复 T#，exit 2 且零写入；可同步补 V9 issue，让结构问题提前暴露。

### B5: IO 失败后的文件完整性未定义
**来源**: 错误路径
**文件**: `dev-pipeline/tasks/progress-engine/plan.md`
**位置**: 第 72、79、112 行
**严重程度**: P1
**根因分类**: spec 缺口
**置信度**: 高

**问题描述**：
plan 规定解析错误不写文件，也把 IO 错误归入 exit 2；它没有要求写临时文件后 `os.replace`。直接覆盖 checklist 时，磁盘写失败可留下截断文件。

**修复建议**：
所有校验通过后生成完整新内容，写同目录临时文件并 flush/close，再用 `os.replace` 原子替换；任何失败清理临时文件并保持原文件字节不变。文件锁继续保持范围外。

### B6: JSON 与幂等输出缺少可测试定义
**来源**: OpenSpec CLI 契约
**文件**: `dev-pipeline/tasks/progress-engine/plan.md`
**位置**: 第 76-79、114 行
**严重程度**: P2
**根因分类**: spec 缺口
**置信度**: 高

**问题描述**：
`downgraded` 若表示本次实际写入，首跑包含 T2、二跑为空，和“文件与输出一致”冲突。三个数组的元素类型、排序、重复 issue 去重规则也未定义。

**修复建议**：
定义稳定 schema。推荐让 `targets` 表示当前报告要求降级的有序去重 T#，`changed` 表示本次真实写入；幂等只要求第二次文件无变化和稳定的 `targets/p2_registered/warnings`，`changed` 首跑与二跑允许不同。若坚持整个输出一致，则删除“本次改动”语义。

### B7: 报告选择文法缺少精确边界
**来源**: 输入边界
**文件**: `dev-pipeline/tasks/progress-engine/plan.md`
**位置**: 第 70-71 行
**严重程度**: P2
**根因分类**: spec 缺口
**置信度**: 中

**问题描述**：
报告筛选缺少精确 glob/regex 和非规范文件行为。目录中的备份文件、临时文件或其他 Markdown 文件可能改变“最新报告”的选择结果。

**修复建议**：
只消费精确匹配 `^qa-gate-report-[0-9]{8}-[0-9]{6}\.md$` 的文件，并明确非规范文件采用忽略或 exit 2。

### B8: clean 与提交边界需要对齐仓库规则
**来源**: 当前仓库状态 + OpenSpec 配置
**文件**: `dev-pipeline/tasks/progress-engine/plan.md`
**位置**: 第 17、20-21、117 行
**严重程度**: P2
**根因分类**: spec 缺口
**置信度**: 高

**问题描述**：
当前工作区含无关未跟踪文件，`clean` 是全仓还是目标文件集未定义。OpenSpec 配置要求代码测试、skills、仓库文档三段，plan 列出 planning/A/B/archive 四个生命周期提交。

**修复建议**：
将前置写成“commit 0 后目标路径无未提交改动，记录 HEAD 与基线测试结果”；把 A/B/仓库文档定义为三段实现提交，planning 与 archive 标为生命周期提交。
