## 关键决策

| D-ID | 决策 | 依据 U/J | 选择理由 | 备选与否决原因 | 重评条件 |
|---|---|---|---|---|---|
| D1 | 设备音频运行时独立并唯一拥有 I2S/DMA、采集、播放与缓冲 | `U1`、`U3`、`U5`、`U7`、`J1`、`J3` | 单一硬件 owner 能在取消和故障时原子停 DMA、清缓冲并释放租约 | 由会话与传输分别访问音频驱动：DMA 所有权和释放顺序会分散，barge-in 容易竞态 | 目标 BSP 提供经过 HIL 验证的独占全双工音频服务，且可统一证明取消和资源释放 |
| D2 | 交互会话协调器独立拥有设备轮次状态与 cancel epoch | `U2`、`U7`、`U9`、`J5` | 唤醒、取消、重连和迟到事件需要单一状态事实源维护终态和优先级 | 状态分散在传输与播放器：取消 epoch 和当前 turn 缺少单点仲裁 | 平台提供可验证的权威轮次状态机，并覆盖 barge-in、重连和迟到事件 |
| D3 | 设备双工传输作为独立模块承载帧、确认、背压、控制优先级和续传 | `U3`、`U5`、`U6`、`U7`、`U9`、`J2`、`J3`、`J6` | 网络可靠性策略可独立压测和替换，同时避免弱网状态污染业务轮次协调 | 合并进交互会话协调器：网络重试、窗口和背压会与业务状态耦合，测试与替换成本上升 | 目标平台 SDK 原生提供帧序号、确认、背压、控制优先级和断线续传，并达到本包验收 |
| D4 | 服务端语音网关独立拥有连接与服务端 turn 终态并编排 ASR/TTS | `U3`、`U4`、`U5`、`U7`、`U9`、`J5` | 单一网关 owner 可在供应商回调、取消和重连并发时保护吸收终态 | 设备直接调用 ASR/TTS 或适配器各自管理 turn：终态与背压责任分散 | 上游平台提供统一的连接、turn 终态、取消传播和背压编排契约 |
| D5 | ASR 供应商能力封装在独立适配器 | `U4`、`U7`、`U9`、`J4` | 隔离供应商流式输入、取消、错误码和幂等差异 | 网关直接调用 ASR SDK：供应商语义进入核心状态机并扩大替换面 | 确定长期单一 ASR 且其 SDK 契约与网关协议完全一致 |
| D6 | TTS 供应商能力封装在独立适配器 | `U5`、`U7`、`U9`、`J4` | 隔离首块、块序、取消、超时和输出格式差异 | 网关直接调用 TTS SDK：迟到块与取消差异进入核心状态机 | 确定长期单一 TTS 且其 SDK 原生满足首块、取消和顺序契约 |
| D7 | 端到端遥测作为跨设备和服务端的独立契约模块 | `U6`、`U8`、`U9`、`J7` | 统一关联标识、事件 schema、指标和脱敏规则，支持跨边界重建轮次 | 各模块自行记录日志：字段、采样、关联与隐私规则会漂移 | 观测平台提供跨端统一 schema、关联、脱敏和有界设备队列能力 |

## 模块详情

### 模块：设备音频运行时

**职责**：提供唯一音频 HAL 与资源 owner；在启动时探测板型能力；把麦克风样本扇出给唤醒检测和活动轮次；管理播放 DMA、上下行环形缓冲与播放静音。

**包含范围**：StackChan ESP32-S3 board profile、codec/I2S 初始化、采样/播放格式、DMA 描述符、麦克风扇出、上行环形缓冲、下行抖动缓冲、启动自检、资源水位。

**排除范围**：唤醒模型训练、网络协议、ASR/TTS 调用、会话终态决策。

**依赖**：目标板 BSP 与 codec 驱动；Q1 的板型、引脚、内存、全双工和 AEC 决策。

**边界类/对外契约**：`AudioRuntimeBoundary`

**核心接口与数据**：

- 输入：`StartCapture(turn_id, format)`、`StopCapture(reason)`、`AcquirePlayback(turn_id, stream_id, epoch)`、`PushPlaybackFrame(frame)`、`AbortPlayback(turn_id, epoch)`。
- 输出：20 ms `CapturedAudioFrame`、`WakeEvent`、`PlaybackAudibleStarted`、`PlaybackEnded`、`AudioFault`、缓冲与 DMA 指标。
- 拥有的数据：board capability、当前采集/播放租约、I2S/DMA handle、上行环形缓冲、下行抖动缓冲、播放 accepted epoch。

**风险与依据**：高。播放期间仍需持续采集唤醒信号，硬件全双工、AEC、内存和 DMA 调度直接决定 barge-in 与延迟 SLO。

**状态**：可进入 x-req

**决策回指**：`D1`

**回指 Requirement**：`平台适配`、`音频采集与上行`、`流式合成与播放`、`可测量低延迟`、`播放期打断`、`波动恢复与稳定运行`

### 模块：交互会话协调器

**职责**：作为设备状态事实源处理唤醒、utterance end、网络变化、播放事件、超时和取消；原子更新 `current_turn_id` 与 `cancel_epoch`；安排本地先停播、控制消息后传播、新轮次再采集。

**包含范围**：设备状态机、轮次 ID、取消终态、barge-in 入口、超时器、音频租约编排、恢复决策和状态事件。

**排除范围**：音频驱动细节、帧重传实现、服务端适配器实现。

**依赖**：`设备音频运行时` 提供音频资源边界；`设备双工传输` 提供控制优先队列与连接状态。

**边界类/对外契约**：`InteractionSessionBoundary`

**核心接口与数据**：

- 输入：`WakeEvent`、`UtteranceEnded`、`TransportStateChanged`、`TtsStreamStarted/Ended`、`Timeout`、`BufferFault`。
- 输出：`Start/StopCapture`、`Open/CancelTurn`、`Acquire/AbortPlayback`、`StateTransitionEvent`、`RecoveryDecision`。
- 拥有的数据：设备状态、`current_session_id`、`current_turn_id`、`cancel_epoch`、活动 stream 集合、超时器和终态原因。

**风险与依据**：高。唤醒、迟到帧、取消确认、连接断开和新轮次可并发到达，状态 owner 与事件优先级必须唯一。

**状态**：可进入 x-req

**决策回指**：`D2`

**回指 Requirement**：`唤醒进入监听`、`播放期打断`、`可测量低延迟`、`端到端可观测`、`波动恢复与稳定运行`

### 模块：设备双工传输

**职责**：维持一条设备到网关的双工安全连接；协商能力；发送音频与控制帧；通过序号、累计确认、窗口、去重和重连游标提供有界恢复。

**包含范围**：TLS/WebSocket 客户端、能力握手、消息 envelope、控制优先发送、确认窗口、重传缓存、下行序号检查、心跳、退避重连和背压信号。

**排除范围**：音频编解码算法、业务状态终态决策、服务端 ASR/TTS 供应商逻辑。

**依赖**：`设备音频运行时` 提供/消费音频帧；`交互会话协调器` 提供有效轮次与 epoch；`服务端语音网关` 实现对端协议。

**边界类/对外契约**：`DeviceStreamTransport`

**核心接口与数据**：

- 输入：`OpenTurn`、`CapturedAudioFrame`、`EndOfUtterance`、`CancelTurn`、当前有效 epoch。
- 输出：`AsrFinal`、`TtsAudioFrame`、`StreamEnd/Error`、`AckCursor`、`TransportStateChanged`、背压与重连指标。
- 拥有的数据：`connection_id`、协商能力、发送窗口、最高连续确认序号、接收重排窗口、心跳与退避状态；轮次有效性由协调器拥有。

**风险与依据**：高。PCM 带宽、弱网重传和设备 RAM 相互约束；控制消息必须抢占旧音频队列才能保证取消语义。

**状态**：可进入 x-req

**决策回指**：`D3`

**回指 Requirement**：`音频采集与上行`、`流式合成与播放`、`可测量低延迟`、`播放期打断`、`端到端可观测`、`波动恢复与稳定运行`

### 模块：服务端语音网关

**职责**：认证设备连接，成为服务端 session/turn owner，按关联标识接收音频，驱动 ASR→TTS 流水线，优先处理取消，限制每轮队列并输出统一错误。

**包含范围**：连接注册、协议校验、音频去重/确认、turn 状态、适配器编排、取消广播、TTS 下行发送窗口、重连恢复游标和服务断路。

**排除范围**：ASR/TTS 模型内部实现、设备硬件状态、长周期对话记忆。

**依赖**：`设备双工传输` 的对端契约；`ASR 适配器`、`TTS 适配器`；`端到端遥测`。

**边界类/对外契约**：`VoiceGatewayBoundary`

**核心接口与数据**：

- 输入：`Hello/Resume`、`OpenTurn`、`UplinkAudioFrame`、`EndOfUtterance`、`CancelTurn`、`AckDownlink`。
- 输出：`AckUplink`、`AsrFinal`、`DownlinkAudioFrame`、`StreamEnd`、`CancelAck`、`StructuredError`。
- 拥有的数据：连接到设备的绑定、活动 turn 状态、上行去重游标、下行发送窗口、取消终态、适配器调用 handle 和 per-turn 配额。

**风险与依据**：高。网关必须在多回调并发时串行化终态，防止取消后的 ASR/TTS 回调重新打开下行。

**状态**：可进入 x-req

**决策回指**：`D4`

**回指 Requirement**：`音频采集与上行`、`服务端语音识别`、`流式合成与播放`、`可测量低延迟`、`播放期打断`、`端到端可观测`、`波动恢复与稳定运行`

### 模块：ASR 适配器

**职责**：把统一音频帧和结束标记映射到供应商 ASR 流；规范 final text、超时、取消、错误码、幂等键和供应商指标。

**包含范围**：供应商连接、格式适配、流式写入、final 回调、3 秒无进展超时、取消 handle、首个结果前的一次有资格重试。

**排除范围**：音频上行可靠性、TTS 调用、文本内容生成策略。

**依赖**：`服务端语音网关` 提供已验证且有序的轮次音频；Q4 提供供应商能力和配额。

**边界类/对外契约**：`AsrBoundary`

**核心接口与数据**：

- 输入：`BeginAsr(turn_context, format, idempotency_key)`、`WriteAudio(frame)`、`FinishInput`、`Cancel(reason)`。
- 输出：唯一 `AsrFinal(text_ref, timing)` 或 `AsrFailure(code, retryable)`，以及供应商 request ID。
- 拥有的数据：供应商流 handle、幂等键、输入进度、超时器和 terminal 标记；文本内容所有权在网关轮次上下文中。

**风险与依据**：中。供应商可能只提供弱取消或非幂等调用，适配器必须把迟到回调转为可观测丢弃。

**状态**：可进入 x-req

**决策回指**：`D5`

**回指 Requirement**：`服务端语音识别`、`可测量低延迟`、`播放期打断`、`端到端可观测`、`波动恢复与稳定运行`

### 模块：TTS 适配器

**职责**：把有效文本引用映射到供应商 TTS 流，尽快交付首块，把音频规范化为单一 stream 格式并响应取消。

**包含范围**：供应商调用、首块 3 秒超时、块间隔 1 秒超时、格式声明、顺序编号、结束标记、取消 handle、首块前的一次有资格重试。

**排除范围**：设备播放缓冲、下行网络重传、音色训练。

**依赖**：`服务端语音网关` 提供有效 final text 与 turn 终态；Q4 提供供应商能力和配额。

**边界类/对外契约**：`TtsBoundary`

**核心接口与数据**：

- 输入：`BeginTts(turn_context, text_ref, output_format, idempotency_key)`、`Cancel(reason)`。
- 输出：`TtsStreamStarted(format)`、有序 `TtsChunk`、`TtsStreamEnded` 或 `TtsFailure(code, retryable)`。
- 拥有的数据：供应商调用 handle、当前输出格式、块序号、首块/块间超时器和 terminal 标记。

**风险与依据**：中。供应商的取消和流式边界可能产生迟到块，网关终态检查仍是最后一道过滤。

**状态**：可进入 x-req

**决策回指**：`D6`

**回指 Requirement**：`流式合成与播放`、`可测量低延迟`、`播放期打断`、`端到端可观测`、`波动恢复与稳定运行`

### 模块：端到端遥测

**职责**：统一设备与服务端事件 schema、关联标识、时间戳、错误码、指标名和脱敏规则，支持从单轮次复算延迟与资源释放。

**包含范围**：结构化事件、设备 bounded event queue、服务端 trace/span、状态转换、帧/字节、重试/重连、缓冲高水位、underrun/overrun、late-drop、资源 gauge 和成功采样/错误全量策略。

**排除范围**：原始音频留存、完整文本日志、具体观测平台采购。

**依赖**：所有模块在边界操作时发事件；Q5 提供设备身份、留存和脱敏策略。

**边界类/对外契约**：`VoiceTelemetryBoundary`

**核心接口与数据**：

- 输入：`VoiceEvent(correlation, state, reason, monotonic_ts, wall_ts, attrs)`、metric sample、资源 snapshot。
- 输出：可按轮次查询的事件序列、trace、P50/P95/P99 延迟、错误率、恢复率、缓冲/资源高水位和隐私审计结果。
- 拥有的数据：事件 schema、错误码表、指标定义、采样规则、设备批量上传队列和服务端观测 sink 配置。

**风险与依据**：中。跨设备时钟不可直接相减；端到端使用设备同一单调时钟，服务段使用服务端同一单调时钟，并单独上报时钟同步质量。

**状态**：可进入 x-req

**决策回指**：`D7`

**回指 Requirement**：`平台适配`、`唤醒进入监听`、`音频采集与上行`、`服务端语音识别`、`流式合成与播放`、`可测量低延迟`、`播放期打断`、`端到端可观测`、`波动恢复与稳定运行`
