# 质量属性与验收口径

## 1. 参考环境

性能数字以以下参考环境为前提，最终硬件和网络确认后重新冻结：

- 设备与接入点信号稳定，往返时延不高于 80 ms，丢包率不高于 1%，可用上行带宽不低于 128 kbps。
- 服务端同区域部署且无资源过载，ASR/TTS 供应商满足流式接口能力。
- 音频为单声道语音，帧长 20–40 ms；具体编解码与采样率待确认。
- 性能以设备单调时钟和服务端追踪事件计算，统计窗口至少包含 1,000 个有效话轮。

## 2. 低延迟指标

| ID | 指标起止点 | P0 目标 |
|---|---|---|
| PERF-001 | 本地唤醒命中 → 首个采集帧进入上行队列 | p95 ≤ 100 ms |
| PERF-002 | 音频帧采集完成 → 服务端网关收到 | p95 ≤ 250 ms |
| PERF-003 | 设备发送 `audio_end` → 服务端发布 `asr_final` | p95 ≤ 800 ms，p99 ≤ 1,500 ms |
| PERF-004 | `asr_final` → 首个 TTS 音频帧到达设备 | p95 ≤ 1,000 ms，p99 ≤ 2,000 ms |
| PERF-005 | 首个 TTS 帧到达 → 扬声器输出首个样本 | p95 ≤ 250 ms |
| PERF-006 | 本地打断事件 → 扬声器静音 | p95 ≤ 150 ms，最大 ≤ 250 ms |
| PERF-007 | 本地打断事件 → 服务端记录旧响应已取消 | p95 ≤ 600 ms（参考网络下） |

端到端体验主指标为 `audio_end → 首个可听 TTS 样本`，目标 p95 ≤ 2,000 ms。该指标分解展示 ASR、响应文本生成、TTS 首块、网络和设备起播耗时。

## 3. 稳定性与可恢复性

| ID | 质量要求 | P0 验收阈值 |
|---|---|---|
| REL-001 | 参考环境下完成话轮成功率 | ≥ 99.0%，排除用户主动取消 |
| REL-002 | 旧代际音频在打断后重新出声 | 0 次 |
| REL-003 | 可恢复窗口内的短暂断线恢复连接 | 95% 在 5 秒内恢复，99% 在 15 秒内恢复 |
| REL-004 | 失败话轮收敛回可再次唤醒状态 | 100% 在 10 秒内完成，认证硬失败除外 |
| REL-005 | 连续运行 | 72 小时压力运行，无内存持续增长、死锁、看门狗循环或队列无界增长 |
| REL-006 | 重试副作用 | 0 个重复最终 ASR、重复响应生成和重复播放终态 |
| REL-007 | 服务依赖故障隔离 | 单一 ASR/TTS 故障不导致设备连接进程或其他会话级联失效 |

建议的默认有界参数待硬件实测冻结：上行未确认音频 2–5 秒，下行领先播放位置 2–5 秒，会话恢复窗口 30–120 秒，最大单次收音 30 秒。

## 4. 可观测性

### 4.1 端到端事件

每个话轮至少产生以下结构化事件，并携带 `device_id`（脱敏/散列）、`session_id`、`trace_id`、`utterance_id`、`response_id`（适用时）、固件版本和协议版本：

- `wake_detected`
- `listen_started`
- `first_audio_sent`
- `audio_ended`
- `asr_started` / `asr_final` / `asr_failed`
- `response_started` / `response_completed` / `response_failed`
- `tts_started` / `first_tts_chunk` / `tts_completed` / `tts_failed`
- `playback_started` / `playback_ended`
- `interrupt_detected` / `cancel_acknowledged`
- `connection_lost` / `recovery_completed`

事件同时带单调时间和可用的墙上时间；跨设备阶段以服务端接收时间校正，原始时间保留用于诊断。

### 4.2 指标

- 延迟：第 2 节所有阶段的 p50/p95/p99。
- 流质量：上行丢帧/重放/乱序，下行欠载/丢弃旧代际/解码错误。
- 资源：设备堆内存/PSRAM 低水位、CPU、各队列水位、看门狗和重启原因。
- 连接：在线设备数、重连次数、重连耗时、心跳 RTT、认证和协议失败率。
- 服务：ASR/TTS/响应生成的成功率、超时率、熔断状态、首结果延迟和并发量。
- 体验：唤醒后无有效收音、话轮成功率、打断率、打断静音延迟和恢复后重试率。

### 4.3 告警与诊断

- 任一 P0 延迟或成功率在连续窗口内越过阈值时告警，并可按固件、硬件、网络区域和供应商切片。
- 设备保留最近关键事件的有界环形缓冲，崩溃或恢复后上报摘要。
- 统一追踪可从单个 `trace_id` 还原阶段、重试、取消、序号缺口与终态。
- 原始音频默认不记录；临时诊断采样需要显式授权、限时开启、加密保存和审计记录。

## 5. 安全与隐私

| ID | 要求 |
|---|---|
| SEC-001 | 全链路使用当前受支持的 TLS 配置，设备验证服务端身份。 |
| SEC-002 | 每台设备具有可撤销的独立凭据；凭据不写入日志和遥测。 |
| SEC-003 | 服务端从认证上下文绑定 `device_id`，拒绝消息体中不一致的身份。 |
| SEC-004 | 网关限制消息尺寸、速率、连接数、音频时长和恢复缓存占用。 |
| SEC-005 | 原始音频与 ASR 文本遵循数据最小化；默认只处理实时链路，不长期保存。 |
| SEC-006 | 需要保存文本或诊断音频时，明确用户授权、用途、保留期、访问审计和删除机制。 |
| SEC-007 | 错误、追踪和指标对用户文本、网络地址、设备凭据执行脱敏。 |
| SEC-008 | 固件和协议降级受到策略控制，已知不安全版本无法重新协商启用。 |

## 6. 验收场景

每个场景均应核对设备最终状态、服务端终态、音频输出、指标和完整追踪。

### ACC-001 正常话轮

- 条件：参考网络，ASR/响应生成/TTS 健康。
- 操作：唤醒、说出 3–8 秒语音、自然停顿。
- 通过：产生唯一最终文本和唯一响应；音频连续播放；所有阶段标识可串联；延迟满足 PERF 指标。

### ACC-002 播放中打断

- 条件：TTS 正在播放，服务端持续发送旧响应帧。
- 操作：用户触发新一轮 listen。
- 通过：设备在 PERF-006 时间内静音并收新语音；旧响应帧持续到达也无再次出声；服务端旧响应进入 `cancelled`；新话轮独立完成。

### ACC-003 上行短暂断网

- 条件：正在上传 8 秒语音。
- 操作：中断网络 2 秒后恢复，未确认帧仍在设备缓冲范围内。
- 通过：恢复握手给出确认点，帧重放无重复识别，话轮完成；追踪展示断线和重放范围。

### ACC-004 上行不可恢复缺口

- 条件：上传期间断网超过本地缓冲能力。
- 操作：恢复网络。
- 通过：服务端返回 `restart_utterance`；当前话轮进入明确失败终态；设备在 REL-004 时间内回到 `READY`，无截断语音被当作完整输入。

### ACC-005 下行断网与迟到帧

- 条件：TTS 播放中断网，随后创建新代际。
- 操作：恢复网络并注入旧 `response_id/generation` 帧。
- 通过：旧帧全部丢弃；新代际播放正常；丢弃计数可观测。

### ACC-006 ASR 超时

- 条件：ASR 接收音频后无最终结果。
- 操作：等待超过 ASR 超时。
- 通过：话轮进入 `timed_out`；设备收到稳定错误并恢复 `READY`；连接保持可用；同一话轮不会迟到发布最终文本。

### ACC-007 TTS 首帧和中途失败

- 条件：分别模拟 TTS 首帧超时与播放中供应商断流。
- 通过：响应进入明确终态，播放缓冲清理，设备可立即开始新话轮，依赖熔断指标可见。

### ACC-008 慢设备与背压

- 条件：降低设备解码/播放消费速度。
- 操作：持续发送长 TTS。
- 通过：服务端遵守下行窗口；队列容量不越界；达到策略阈值后受控终止；实时控制消息仍可传递。

### ACC-009 重复与乱序消息

- 条件：重复 `listen_start/cancel/audio_end`，并在允许窗口内外注入乱序帧。
- 通过：最终结果唯一；窗口内帧正确重排，窗口外缺口触发明确错误；状态机不回退。

### ACC-010 设备重启与旧连接

- 条件：活动话轮中设备重启，旧连接迟到发送消息。
- 通过：新启动标识建立新会话；旧连接被替换或拒绝；旧话轮无法进入新会话播放器。

### ACC-011 72 小时稳定性

- 条件：混合正常话轮、打断、网络抖动、ASR/TTS 注入故障和服务端滚动升级。
- 通过：满足 REL-005；资源水位无持续劣化；所有失败均有终态和追踪；测试结束后设备可正常完成话轮。

## 7. 发布门禁

发布候选需同时满足：

- 所有 P0 功能需求有可追溯验收证据。
- ACC-001 至 ACC-011 全部通过，旧代际复播计数为 0。
- 参考环境下性能和稳定性指标达到阈值。
- 设备内存、队列和重连退避参数经过目标硬件压力测试。
- 安全评审确认认证、数据最小化、日志脱敏和版本策略。
- 监控面板、告警、追踪查询和故障运行手册在测试环境演练完成。
