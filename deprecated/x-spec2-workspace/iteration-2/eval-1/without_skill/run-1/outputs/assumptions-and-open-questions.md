# 假设、待确认项与决策门槛

## 1. 当前方案假设

| ID | 假设 | 影响 |
|---|---|---|
| ASM-001 | 目标开发板为带 Wi-Fi 和足够 PSRAM 的 ESP32-S3 StackChan 兼容硬件，麦克风与扬声器可同时工作。 | 决定全双工采播、缓冲和 AEC 可行性。 |
| ASM-002 | 音频前端能获得扬声器参考信号，并可执行适合目标硬件的 AEC/NS/AGC。 | 决定播放期间语音唤醒和低误触打断质量。 |
| ASM-003 | 唤醒词检测在设备本地运行，网络故障不会影响唤醒检测。 | 支撑本地优先打断和离线可恢复入口。 |
| ASM-004 | 设备与服务端之间允许维持 TLS 全双工长连接。 | 支撑低延迟并发上行、下行和取消控制。 |
| ASM-005 | ASR 接口支持流式音频输入，TTS 接口支持流式音频输出与取消。 | 决定首结果延迟和取消资源释放能力。 |
| ASM-006 | “根据文字生成 TTS”表示先根据 ASR 文本生成响应文本，再对响应文本合成语音。 | 引入独立响应文本生成组件；业务逻辑仍待定义。 |
| ASM-007 | 设备在网络长期不可用时提示连接异常并等待恢复，不保存完整用户语音用于以后上传。 | 限制隐私风险和设备存储占用。 |
| ASM-008 | 服务端允许保存短期会话状态和有限 TTS 片段以支持短时恢复。 | 决定恢复窗口和服务端内存成本。 |
| ASM-009 | StackChan 表情/动作通过状态事件异步联动，不处于语音实时链路的阻塞路径。 | 动画故障不会拉高语音延迟。 |
| ASM-010 | 设备凭据在烧录或配网阶段安全注入，可独立撤销。 | 决定设备认证与吊销方案。 |

## 2. 待确认项

| ID | 待确认问题 | 建议默认值/方向 | 决策门槛 |
|---|---|---|---|
| Q-001 | 具体 StackChan/ESP32-S3 型号、麦克风/扬声器 Codec、PSRAM 和 I2S 通道配置是什么？ | 选择支持同时采播和扬声器参考回路的版本。 | 架构冻结前必须确认。 |
| Q-002 | 播放中打断的触发方式覆盖唤醒词、任意语音、实体按键中的哪些？ | P0 支持唤醒词和按键；任意语音依赖 AEC 实测。 | 验收口径冻结前必须确认。 |
| Q-003 | 上行音频采用 PCM、Opus 或其他编码？采样率和帧长是多少？ | 以 16 kHz 单声道、20–40 ms 帧作为评测起点；编码由芯片负载和带宽实测选择。 | 协议冻结前必须确认。 |
| Q-004 | 下行 TTS 音频格式是什么？设备是否具备硬件或稳定软件解码能力？ | 优先选择低解码开销、可分片、供应商稳定输出的格式。 | 协议冻结前必须确认。 |
| Q-005 | 响应文本生成组件是固定规则、业务 API、LLM 还是直接复述识别文本？ | 保持可插拔服务边界，默认由外部业务服务提供响应文本。 | 产品需求冻结前必须确认。 |
| Q-006 | ASR 是否需要中间文本、语言自动识别或多语言？ | P0 只依赖唯一最终文本；中间文本作为可选能力。 | ASR 供应商选择前确认。 |
| Q-007 | 允许的最大单次收音、最大 TTS 时长和静音端点参数是多少？ | 收音上限 30 秒；其他参数由体验测试冻结。 | 容量测试前确认。 |
| Q-008 | 可接受的参考网络、目标地区和弱网等级是什么？ | 先采用 RTT≤80 ms、丢包≤1% 的基线，再增加受控弱网档位。 | 性能验收前必须确认。 |
| Q-009 | 活动用户数、并发连接数、峰值话轮率和区域部署规模是多少？ | 采用容量模型输入，避免在本需求包内猜测规模。 | 服务端容量设计前必须确认。 |
| Q-010 | 原始音频、ASR 文本、响应文本和诊断日志的保留策略是什么？ | 原始音频默认不落盘；文本和日志采用最小字段与短保留期。 | 安全评审前必须确认。 |
| Q-011 | Wi-Fi 配网、设备认证凭据注入和凭据轮换由哪个现有系统负责？ | 复用产品设备管理能力，通过稳定接口接入。 | 联调前必须确认。 |
| Q-012 | 网络恢复时需要续播旧 TTS，还是终止并等待用户重新唤醒？ | 短时缓存完整时允许续播；代际变化后永远终止旧响应。 | 体验与服务成本评审时确认。 |
| Q-013 | ASR/TTS 是否支持真正取消，以及取消后的计费和迟到回调语义是什么？ | 适配器吸收差异，上层保持幂等取消和旧结果隔离。 | 供应商合同与适配设计前确认。 |
| Q-014 | 设备是否有安全芯片、可信存储和可靠墙上时钟？ | 协议顺序依赖单调时钟与序号；认证材料使用平台最强可用保护。 | 安全架构冻结前确认。 |

## 3. 关键决策记录

| 决策 | 当前选择 | 理由 | 重新评估触发条件 |
|---|---|---|---|
| 打断位置 | 设备侧先停播，服务端异步取消 | 满足低延迟并隔离网络波动 | 硬件无法持续运行打断检测 |
| 连接模型 | 单条已认证全双工长连接 | 减少握手和多通道一致性成本 | 网关或网络环境限制长连接 |
| 一致性模型 | 业务标识 + 单调代际 + 幂等终态 | 防止重试、迟到帧和重连造成复播 | 协议载荷成本无法接受 |
| 弱网策略 | 有界重放，可恢复则续传，缺口则显式终止 | 资源有界且结果确定 | 产品要求长期离线缓存 |
| 数据策略 | 原始音频默认不持久化 | 数据最小化并降低安全风险 | 获得独立授权与保留需求 |
| 供应商边界 | ASR/TTS 通过适配器接入 | 保持上层状态与协议稳定 | 产品明确长期绑定单一供应商且接受耦合 |

## 4. 需求细化阶段必须保留的约束

- 打断本地生效，无需等待服务端响应。
- 新代际创建后，旧响应永久失去播放资格。
- 音频、控制和遥测队列全部有界，溢出路径可测试。
- 任何重试都以业务幂等键和稳定终态为前提。
- 每个失败路径回到明确设备状态并产生端到端追踪。
- 性能指标按阶段拆解，供应商耗时与设备耗时可独立归因。
- 硬件能力、音频格式和数据保留策略确认后再冻结详细接口。
