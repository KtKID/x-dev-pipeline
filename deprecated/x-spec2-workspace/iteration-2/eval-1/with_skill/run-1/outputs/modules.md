## 关键决策

| D-ID | 决策 | 依据 U/J | 选择理由 | 备选与否决原因 | 重评条件 |
|---|---|---|---|---|---|
| D1 | 设备与网关采用 TLS WebSocket 长连接，文本控制帧与二进制媒体帧按统一信封复用 | `U3`、`U6`、`J5` | 单连接支持双向流、服务器主动下行和较低握手开销，ESP32 客户端生态可承接 | HTTP 分块上传加 SSE：双通道状态与取消协调更复杂；WebRTC：媒体能力完整，但首版设备栈、信令和资源成本更高 | 现有基础设施已统一 gRPC/WebRTC，或网络实测显示 WebSocket 无法满足抖动、代理兼容与时延目标 |
| D2 | 唤醒与首级 VAD 位于设备端，ASR final 位于服务器端并作为文字完成事实源 | `U2`、`U3`、`J2`、`J7` | 本地唤醒与 VAD 缩短入口和尾部延迟，服务器 final 统一供应商差异与下游触发 | 服务端持续监听唤醒：增加常态带宽并削弱断网入口；完全依赖 ASR 端点：尾部时延受远端服务控制 | 板端唤醒/VAD 在目标噪声条件下达不到误唤醒、漏唤醒或 CPU 预算，或 ASR 提供更稳定的低延迟端点能力 |
| D3 | 打断采用“本地先静音与清队列，再取消旧轮次，随后开启新轮次”的顺序，所有结果经过轮次代次门禁 | `U9`、`J1`、`J2`、`J8`、`J11` | 用户感知停止由设备立即完成，代次门禁封住迟到回调，顺序明确消除扬声器所有权竞争 | 等服务器确认后停止：引入网络往返延迟；复用同一轮次继续采音：异步结果归属含混 | 产品要求保留旧回复续播，或板卡回声条件无法在播放期间可靠命中唤醒词 |
| D4 | 每个设备会话只保留一个活动轮次；断线、服务重启或新唤醒都会终止旧轮次，新连接创建新 `connection_epoch` | `U9`、`U11`、`J6`、`J8` | 单活动轮次匹配单扬声器资源，终止旧轮次可避免实时语音重放与陈旧响应 | 断点续传旧轮次：需要保存媒体与供应商状态并处理重复输出；多并发轮次：增加仲裁与资源竞争 | 产品引入多路并行语音、必须跨断线续播的内容，或业务确认陈旧语音仍具价值 |
| D5 | ASR 适配器输出规范化的 partial、唯一 final、错误和取消事件，只有 final 能触发文字编排 | `U4`、`J7`、`J8` | 统一供应商事件并建立唯一完成事实源，可阻止 partial 抖动和迟到结果触发重复 TTS | 每个 partial 驱动 TTS：可能降低首包延迟，但会产生改写、撤销和重复语音 | 选定供应商支持稳定增量语义与可修正 TTS，且实测收益足以覆盖复杂度 |
| D6 | 首版文字策略为 ASR final 直通 TTS，文字策略与 TTS 供应商均通过独立端口隔离 | `U5`、`J3` | 直接形成可验收闭环，同时为后续 LLM、业务回答或文本规范化提供清晰插入点 | 在会话网关内硬编码直通：边界耦合；首版直接接入对话模型：需求语义和时延预算尚未确认 | 用户确认需要智能回复、翻译、内容过滤或其他文字处理语义 |
| D7 | 全链路使用 `device_id + connection_epoch + session_id + turn_id + stream_id + seq` 关联，并以结构化事件和指标为默认观测载体 | `U10`、`J10` | 标识层级覆盖重连、轮次、媒体流与帧，可在关闭内容日志时重建处理时序 | 只用服务端 trace id：设备离线和重连前事件难关联；默认保存音频与全文：隐私与容量成本更高 | 合规策略要求更强匿名化，或调试目标需要经授权的采样内容链路 |
| D8 | 设备与服务端媒体队列采用有界缓冲和应用层接收窗口；上行溢出终止轮次，下行先暂停生产并在总上限后终止轮次 | `U8`、`U12`、`J9` | 有界队列保护长稳运行，明确溢出语义可避免带缺口语音继续识别或播放 | 无界缓存：资源随波动增长；静默丢弃任意音频：产生不可解释的识别或播放内容 | 目标板卡内存和真实弱网测试给出新的安全水位，或媒体 Codec 支持可靠的可丢弃帧策略 |
| D9 | 初始媒体基线采用 16 kHz 单声道 PCM16、20 ms 帧，握手保留 Codec 与帧时长协商 | `U3`、`U6`、`J4`、`J11` | 基线编解码成本低、链路行为易测，协商契约支持后续压缩格式 | 首版固定 Opus：节省带宽，但引入板端 CPU、内存与编解码时延风险；整段 WAV：阻断流式链路 | PCM 带宽导致目标网络下丢包或时延超标，且 Opus 在目标板卡的 CPU、内存和音质基准达标 |

## 模块详情

### 模块：StackChan 语音会话运行时

**职责**：拥有设备侧 `IDLE`、`LISTENING`、`WAITING_RESPONSE`、`PLAYING`、`INTERRUPTING`、`RECOVERING` 状态；接收本地唤醒事件，分配轮次，协调采集、播放、取消和用户反馈。

**包含范围**：唤醒去抖、状态转换、轮次代次、打断顺序、子资源租约和错误反馈。

**排除范围**：麦克风/I2S 细节、WebSocket 实现、ASR/TTS 供应商调用。

**依赖**：设备音频采集上行、设备流式播放、实时语音传输、端到端遥测。

**边界类/对外契约**：`VoiceSessionRuntime`

**核心接口与数据**：

- 输入：`WakeDetected`、`TransportStateChanged`、`TtsFrameReady`、`RemoteTurnEvent`、本地超时。
- 输出：`StartCapture`、`StopCapture`、`StartPlayback`、`StopPlayback`、`CancelTurn`、本地提示。
- 拥有的数据：当前设备状态、`session_id`、活动 `turn_id`、子资源租约与终态原因。

**风险与依据**：播放期间唤醒需要目标硬件提供足够的声学隔离、回声处理或唤醒模型鲁棒性，见 `J2`、`J11`。

**状态**：可进入 x-req

**决策回指**：`U1`、`D2`、`D3`

**回指 Requirement**：`唤醒进入监听`、`播放即时打断`、`波动后的自动恢复`、`有界资源下持续运行`

### 模块：设备音频采集上行

**职责**：配置音频输入，采集 PCM 样本，执行 VAD 与帧化，为帧附加关联标识、序号和时间戳，并通过有界队列交给传输层。

**包含范围**：采样、DMA 消费、VAD、格式转换、帧化、输入端点与上行溢出处理。

**排除范围**：会话轮次决策、套接字发送、ASR 供应商协议。

**依赖**：StackChan 语音会话运行时、实时语音传输。

**边界类/对外契约**：`AudioCapturePort`、`UplinkMediaProducer`

**核心接口与数据**：

- 输入：采集开始/停止命令、协商媒体格式、传输窗口、麦克风样本。
- 输出：`AudioFrame`、`InputEnd`、VAD 事件、采集与溢出指标。
- 拥有的数据：DMA 读取状态、VAD 状态、上行帧序号与上行缓冲。

**风险与依据**：目标板卡的 Codec、引脚、DMA 和 RAM 仍待清单确认，见 `J4`、`J11`。

**状态**：可进入 x-req

**决策回指**：`D2`、`D8`、`D9`

**回指 Requirement**：`语音采集与有序上行`、`端到端低延迟预算`、`有界资源下持续运行`

### 模块：设备流式播放

**职责**：校验下行帧代次与顺序，维护抖动缓冲，独占扬声器输出，报告消费进度，并在本地打断时立即静音与清队列。

**包含范围**：帧去重/拒旧、抖动缓冲、解码适配、播放水位、扬声器租约和硬停止。

**排除范围**：唤醒判定、网络重连、TTS 生成。

**依赖**：StackChan 语音会话运行时、实时语音传输。

**边界类/对外契约**：`StreamingPlaybackPort`、`SpeakerLease`

**核心接口与数据**：

- 输入：当前轮次上下文、`TtsAudioFrame`、开始/停止命令、音频输出回调。
- 输出：消费确认、接收窗口、播放状态、迟到帧与欠载指标。
- 拥有的数据：当前 `stream_id`、期望序号、抖动缓冲、扬声器租约与播放水位。

**风险与依据**：抖动水位与音频硬件时钟共同影响首包延迟和欠载，需要真实板卡调优，见 `J1`、`J11`。

**状态**：可进入 x-req

**决策回指**：`D3`、`D8`、`D9`

**回指 Requirement**：`设备有序播放`、`播放即时打断`、`端到端低延迟预算`、`有界资源下持续运行`

### 模块：实时语音传输

**职责**：管理设备到网关的连接生命周期，编码/解析协议信封，复用控制与媒体，维护心跳、连接代次、应用层窗口和重连退避。

**包含范围**：TLS WebSocket、握手协商、消息校验、心跳、流控、超时、重连和协议错误。

**排除范围**：轮次业务状态、音频采样/播放、供应商服务重试。

**依赖**：无业务模块依赖；运行时依赖平台网络栈和服务器 WebSocket 基础设施。

**边界类/对外契约**：`RealtimeVoiceTransport`、`VoiceWireProtocol`

**核心接口与数据**：

- 输入：控制命令、上行媒体帧、接收窗口、套接字与心跳事件。
- 输出：连接状态、已解析控制事件、下行媒体帧、发送确认和协议错误。
- 拥有的数据：`connection_epoch`、连接状态、握手能力、发送队列、接收窗口与退避状态。

**风险与依据**：代理超时、弱网重排序和设备 TLS 内存占用需要集成测试，见 `J5`、`J9`。

**状态**：可进入 x-req

**决策回指**：`D1`、`D4`、`D8`

**回指 Requirement**：`语音采集与有序上行`、`TTS 音频流式下行`、`波动后的自动恢复`、`端到端低延迟预算`

### 模块：服务端会话网关

**职责**：建立设备会话，拥有服务端轮次状态，校验所有消息代次，编排 ASR 和 TTS，传播取消，执行终态幂等和下行流控。

**包含范围**：握手、连接到设备映射、单活动轮次、输入路由、供应商编排、取消门禁、终态和错误映射。

**排除范围**：ASR/TTS 供应商 SDK 细节、设备硬件状态、遥测后端存储实现。

**依赖**：实时语音传输、流式 ASR 适配器、文字到 TTS 编排、端到端遥测。

**边界类/对外契约**：`VoiceSessionGateway`、`TurnCoordinator`

**核心接口与数据**：

- 输入：连接事件、控制消息、上行媒体帧、ASR/TTS 规范化事件、超时。
- 输出：适配器命令、下行控制与媒体、终态、结构化遥测。
- 拥有的数据：连接到会话映射、当前轮次状态、取消令牌、流窗口和终态原因。

**风险与依据**：取消、断连和供应商回调并发会形成竞态，所有异步入口都需执行 `J8` 的活动轮次校验。

**状态**：可进入 x-req

**决策回指**：`D1`、`D4`

**回指 Requirement**：`流式 ASR 产出文字`、`最终文字触发 TTS`、`TTS 音频流式下行`、`播放即时打断`、`波动后的自动恢复`

### 模块：流式 ASR 适配器

**职责**：把规范音频帧映射为供应商流式请求，并把供应商差异归一为 partial、final、错误、超时和取消事件。

**包含范围**：SDK 会话、格式映射、输入结束、结果归一、期限、有限重试和取消。

**排除范围**：设备 VAD、文字业务策略、TTS 调用。

**依赖**：服务端会话网关提供轮次上下文和取消令牌。

**边界类/对外契约**：`StreamingAsrPort`

**核心接口与数据**：

- 输入：`OpenAsrStream`、有序 `AudioFrame`、`InputEnd`、`Cancel`。
- 输出：`AsrPartial`、`AsrFinal`、`AsrError`、阶段指标。
- 拥有的数据：供应商请求句柄、最终结果门闩、期限和重试计数。

**风险与依据**：供应商对断流、final 和取消的定义不同，适配器必须提供唯一 final 契约，见 `D5`。

**状态**：可进入 x-req

**决策回指**：`D5`

**回指 Requirement**：`流式 ASR 产出文字`、`波动后的自动恢复`、`端到端低延迟预算`

### 模块：文字到 TTS 编排

**职责**：接收唯一 ASR final，执行文字规范化与可插拔策略，创建流式 TTS 请求并增量产出规范音频块。

**包含范围**：空文字处理、文字策略端口、TTS SDK 适配、音频格式归一、首包前有限重试、取消和期限。

**排除范围**：具体对话模型与业务回复逻辑、设备播放、会话终态所有权。

**依赖**：服务端会话网关提供活动轮次门禁、下行窗口和取消令牌。

**边界类/对外契约**：`TextResponsePolicy`、`StreamingTtsPort`

**核心接口与数据**：

- 输入：`AsrFinalText`、媒体能力、下行窗口、`Cancel`。
- 输出：`TtsStreamStarted`、`TtsAudioChunk`、`TtsCompleted`、`TtsError`。
- 拥有的数据：规范化文字摘要、供应商请求句柄、`stream_id`、序号与首块标记。

**风险与依据**：直通语义由 `J3` 暂定；供应商首包延迟与流式格式影响 `J1` 预算。

**状态**：可进入 x-req

**决策回指**：`D6`

**回指 Requirement**：`最终文字触发 TTS`、`TTS 音频流式下行`、`波动后的自动恢复`、`端到端低延迟预算`

### 模块：端到端遥测

**职责**：为设备与服务器提供统一关联上下文、状态事件、指标名称、错误分类、时延计算和有界离线摘要补传。

**包含范围**：事件模型、关联标识、阶段时间戳、时钟偏差记录、资源水位、错误码、隐私默认值和补传去重。

**排除范围**：具体日志/指标供应商、长期数据仓库和内容录音平台。

**依赖**：各业务模块提供事件；部署环境提供服务端日志、指标和追踪接收器。

**边界类/对外契约**：`VoiceTelemetrySink`、`TraceContext`

**核心接口与数据**：

- 输入：状态转换、阶段时间戳、错误、重试、缓冲水位、资源水位和版本信息。
- 输出：设备摘要事件、服务端结构化日志、指标、追踪 span 与告警标签。
- 拥有的数据：设备侧有界事件环、补传游标、指标聚合状态和内容采集开关。

**风险与依据**：设备与服务器时钟域不同，端到端时延需记录同步误差；内容采集遵循 `J10`。
