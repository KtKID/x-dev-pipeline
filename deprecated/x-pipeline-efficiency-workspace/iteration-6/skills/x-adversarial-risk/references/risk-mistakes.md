# 对抗性风险示例卡

每张卡只用于构造候选。当前 Spec 的事实、不变量和可观察结果决定适用性与 Scenario。

## AR-001: 分阶段提交替换窗口

- 标签：phased-commit
- 信号：一个逻辑提交跨多个持久化替换或外部副作用。
- 不变量：任一崩溃点后，已确认状态可恢复且序列保持单调一致。
- 最小反例：完成前一持久化动作后崩溃，重启并继续下一次合法提交。
- 检查：Scenario 可判定重放边界、重复前缀处理和后续提交结果。

## AR-002: 结构合法但语义不可能的快照

- 标签：semantic-snapshot
- 信号：快照通过格式与类型校验，同时包含合法状态转换无法产生的字段组合。
- 不变量：快照状态、版本和历史可由合法操作序列重放得到。
- 最小反例：保持结构合法，只制造一个状态、版本或历史关系冲突。
- 检查：Scenario 可判定语义拒绝结果，并保持原始持久化证据。

## AR-003: 物理完整但语义非法的末条记录

- 标签：semantic-tail
- 信号：末条日志记录在编码、字段和校验和上完整，同时违反序列或状态转换。
- 不变量：物理完整记录按语义接受或判为损坏，恢复过程保持其字节证据。
- 最小反例：向健康日志追加一条校验和正确、序列跳跃或状态转换非法的完整记录。
- 检查：Scenario 可判定损坏分类、公开错误和日志字节保持。

## AR-004: 失败请求占用幂等标识

- 标签：failed-idempotency
- 信号：失败路径与成功路径共享请求历史、去重记录或幂等键。
- 不变量：未提交请求保留幂等标识的后续合法使用能力。
- 最小反例：先用标识 R 触发失败，再用同一 R 提交合法请求。
- 检查：Scenario 可判定第二次成功、唯一副作用和连续序列。

## AR-005: 公开错误响应契约不完整

- 标签：error-contract
- 信号：错误验收只覆盖 code 或退出码，公开响应还包含状态、字段集合和 message 类型。
- 不变量：每类失败保持稳定响应结构、错误码、消息类型和退出状态。
- 最小反例：返回正确 code，同时改变顶层字段、泄漏额外字段或返回非字符串 message。
- 检查：Scenario 精确判定完整公开响应与退出码。
