## 问题详情

### B1：功能域需要独立于稳定 ID

**来源**：用户未来分类需求 + 当前调用链
**文件**：`skills/x-bug2rag/SKILL.md`
**位置**：第 43-54 行
**严重程度**：P2
**根因分类**：spec 缺口
**置信度**：高

**问题描述**：
当前八类“分类”描述状态机、并发、幂等等失败机制。用户提出的按功能分类更接近认证、存储、网络、CLI 等功能域。两种 taxonomy 服务不同检索和浏览需求。

**影响**：
把功能域写入 ID 会让跨域经验只能选择一个前缀；条目重分类还会改变 ID，并使历史 Spec 来源失效。

**修复建议**：
保留 `AR-NNN` 作为全局稳定 key。继续使用 `分类` 表达失败机制；需要功能分类时增加可选、可多值的 `功能域` 或 `domains` 字段。检索使用关键词、Risk、分类和功能域正文；展示层可以生成 `<domain>/AR-001` 视图。

## 最终结论

- `A-risk-001` 是已删除的 namespace 原型。
- `risk-001` 增加字符长度，仍然缺少功能分类信息。
- `AR-001` 适合作为全局稳定、短小、可追踪的 ID。
- ID 已由脚本自动分配，LLM 聚焦关键词、Risk、场景和分类内容。
- 功能分类应进入独立、多值元数据，保持 ID 生命周期稳定。
