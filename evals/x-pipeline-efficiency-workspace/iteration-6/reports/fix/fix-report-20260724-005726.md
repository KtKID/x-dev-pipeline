# Fix 报告：iteration-6 spec risk skill 修复

> 日期：2026-07-24
> 范围：`skills/x-pipeline-efficiency-workspace/iteration-6`
> 来源 CR：`reports/cr/cr-report-20260724-001732.md`
> 修复类型：skill 契约、模式库、validator、测试

## 根因

四轮执行把对抗阶段的工具与推理轮次压到目标范围，同时删除了隐藏质量依赖的判别信息：双评分锚点、五类 AR 风险、AR ID 来源和 corpus 门禁。Terra 因此把 complexity/importance 评为 4/3，只执行 deep，并只补出两个风险 Scenario。模板头部格式与递归输入完整性缺少强制检查，进一步造成机械评分丢失。

## 修改

1. 保留四轮上限：一次批量读取、一次集中 patch、一次聚合验证、一次回执。
2. 在 x-spec3 和 x-adversarial-risk 中恢复紧凑评分锚点：
   - 锁、幂等、跨进程并发、崩溃恢复、多阶段持久化提交、核心算法任一命中 complexity 5。
   - 本地单用户内部 CLI 命中 importance 1。
   - 任一维度为 5 时 review_budget 为 full。
3. 将风险库压缩为 AR-001..AR-005 五张短示例卡。每张卡只保留标签、信号、不变量、最小反例和检查项；正文不含历史证据路径。
4. v2 Scenario 来源固定为 `adversarial-review (AR-nnn; pattern:<标签>)`，同时保留 ID 追踪和通用模式名称。
5. validator 恢复 `validate-corpus`，新增 `validate-review`，在单次工具调用中聚合 Spec、模式库和来源映射问题。
6. validator 强制 Spec 前七行采用 `> key: value`；x-spec3 要求目录或通配符输入递归覆盖。
7. `agents/openai.yaml` 保持启动入口职责；对抗性定义继续由 `SKILL.md` 提供。
