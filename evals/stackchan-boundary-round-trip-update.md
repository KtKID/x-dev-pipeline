# Eval Case: StackChan 模块边界 Round-trip Update

## 目的

验证未来更新者在缺少原始对话和 transcript 时，能否只依靠正式 x-spec2 包恢复模块边界理由，并安全判断“原地细化还是意图变化”。

## 上下文隔离

- 输入只包含生成后的 `spec.md`、`modules.md`、`design.md` 与当前仓库。
- 不提供首次生成过程、agent transcript、评分记录或用户补充解释。
- 输出只写 `update-assessment.md`，保持原包只读。

## 新证据

目标平台 SDK 已原生提供音频帧序号、累计确认、背压、控制消息优先级和断线续传。候选修改是把“设备双工传输”并入“交互会话协调器”。

## 回答契约

1. 引用包内对应 D 及其 U/J 依据。
2. 恢复原选择、选择理由、备选与否决原因、重评条件。
3. 判断新证据是否满足重评条件。
4. 按需求本质、系统目标和不变量判断原地更新或新建 spec 包。
5. 列出需要同步更新的 J/D、模块职责/依赖/接口、Requirement 覆盖与 design.md 动态模型。

## 失败条件

- 依赖原始对话或 transcript 才能说明边界理由。
- 无法引用包内 U/J/D。
- 只给修改结论，缺少原选择、备选、重评条件或同步范围。
