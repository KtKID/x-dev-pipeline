# 按 CR 报告修复

你是执行管线的 agent。只读下面这些文件，不读仓库里的其他任何文件：

1. `skills/x-fix/SKILL.md`
2. `skills/x-cr/references/report-template.md`
3. `skills/x-qdev/SKILL.md`（只读开头到第 1 节结束）
4. `skills/x-verify-spec/SKILL.md`（只读「问题去向」一节）
5. 题目：`evals/problems/cr-fix/cases.json`

每道题是一个情况和一个问题，按规则回答。`answer` 只能取下面40个值之一：

`B3 不用记`、`B3 也写已修，写明随 B1 一起修好`、`不修，写进回执，建议再跑 x-cr`、`不修，状态改待确认`、`不修，状态改误报不修`、`不改代码，状态改误报不修，写理由和代码位置`、`不用跑测试`、`不行，反例测试要调用项目代码`、`交 x-fix 修`、`修`、`停下，把校验错误交给用户`、`停下，让用户先跑 x-cr`、`先写一条修之前失败、修之后通过的反例测试`、`先问用户再决定`、`再跑 xdev coverage 到改动行 100%`、`再跑一次校验脚本，通过才算完成`、`写 commit 哈希`、`写回同一份 CR 报告对应 Bn 下的修复段，不另建文件`、`写文件和函数，能写行号就写`、`列完计划接着做，不等确认`、`删掉这条失败的测试`、`另写一份 reports/fix/ 修复报告`、`只跑 xdev coverage`、`忽略校验错误继续修`、`按函数名和关键词重新找；找不到改待确认`、`新字段给默认值，原来的配置继续能用`、`状态改待确认`、`状态改待确认，写清卡在哪`、`直接改，必填字段不给默认值`、`等用户确认计划再修`、`自己生成一份 CR 报告再修`、`行，断言被调用就够了`、`走 x-fix`、`走 x-qdev`、`跑项目全量测试，不跑 xdev coverage`、`跳过`、`跳过这条，不记`、`退回开发者修，不走 x-fix`、`重新修一遍`、`顺手一起修掉`

把结果写成一个 JSON 数组，保存到调用方给你的输出路径。不要输出别的文件。格式：

```json
[
  {"id": "F00", "answer": "<上面的值之一>", "reason": "一句话理由"}
]
```
