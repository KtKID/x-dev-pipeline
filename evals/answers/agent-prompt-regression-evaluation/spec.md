# Agent 提示词版本回归评测系统

## 需求说明

### 需求本质

在候选提示词发布前，以可复现、可追溯的配对评测比较当前版本与候选版本，将执行事实、评分结果和发布判断分层保存，使回归风险能够被稳定识别。

### 系统目标

- 对同一任务集分别运行当前提示词与候选提示词，并建立一一对应的配对结果。
- 完整记录任务完成情况、工具调用错误、Token 消耗与执行时间。
- 支持独立重复运行；单任务失败保持局部化，剩余任务继续执行。
- 在执行完成后独立评分，生成逐任务及整体对比，并依据可追溯策略输出发布判断。
- 持久化评测定义、原始事实、评分、对比和判断，支持历史查询与复核。

### 范围边界

**包含**：

- 当前版本、候选版本、任务集快照、执行配置、评分规则与发布策略的评测定义。
- 配对任务调度、重复运行、独立任务执行和失败隔离。
- 完成状态、工具错误、Token、耗时等原始观测的采集与持久化。
- 评分、版本对比、发布判断及历史结果查询。
- 可供后续开发拆解的模块边界、契约和动态模型。

**排除/延后**：

- 提示词内容的创作、优化和候选版本生成。
- 任务集内容的生产、标注和质量治理；本系统消费已准备好的任务集。
- Agent 运行时和工具本身的实现；本系统通过执行适配契约调用它们。
- 自动执行提示词发布、流量切换或回滚；本系统只输出发布判断。
- 可视化界面、通知渠道、具体存储产品和具体隔离技术选型。
- 实现代码、开发 task 与 checklist。

### 关键约束

- 同一个评测运行内，当前版本与候选版本必须使用同一任务集快照和同一执行配置快照（`J1`）。
- 执行阶段只产生原始执行事实，不读取或应用评分规则；评分规则只进入评分阶段（`U12`、`J7`）。
- 每个任务、提示词版本和重复序号形成独立执行尝试；任一尝试失败不得终止其他尝试（`J2`、`J10`）。
- 原始执行事实一经终态写入便不可由评分或发布判断覆盖；派生结果通过规则/策略版本关联（`J7`、`J9`）。
- 发布策略阈值、重复次数、执行超时、并发、保留期和访问控制保持配置化，题目未给出的值采用待确认默认（`J2`、`J8`、`J9`、`J10`）。

### 系统不变量

- 每条候选版本结果都能定位到同一 `pair_id` 下的当前版本结果；双方引用相同的 `task_snapshot_id` 与 `execution_profile_id`。
- 每个执行尝试只有一个不可变终态；失败、超时或取消一旦写入终态便不再重启该 `attempt_id`，再次真实执行必须创建新运行或新重复序号下的独立尝试。
- Token 和耗时来自运行时观测；缺失时显式记录“不可用”及原因，禁止填造数值。
- 评分输入只来自已终态的原始执行结果，评分输出必须关联 `scoring_rule_version`。
- 发布判断只消费已完成的对比结果，且必须关联 `release_policy_version`；缺少有效策略时进入人工复核态。
- 重复运行保留独立的重复序号和执行尝试，不覆盖此前历史。
- 单个执行尝试的失败不能阻止同一评测中其他任务、另一提示词版本或其他重复序号进入终态。

| J3 | 任务完成情况至少区分 `succeeded`、`failed`、`timed_out`、`cancelled`，并保留失败原因 | LLM 推断 | 二值完成标记不足以区分执行失败、超时和取消，也无法支持可靠故障分析 | 待确认 |

| J5 | Token 指标包含输入、输出和总量；运行时无法提供时写入不可用原因 | LLM 推断 | 题目未定义 Token 口径，输入/输出拆分便于解释差异，显式缺失可避免伪造统计 | 待确认 |
| J6 | 执行耗时使用单调时钟测量墙钟时长，并同时记录开始、结束时间用于审计 | LLM 推断 | 单调时钟避免系统时间调整污染时长；时间戳支持历史定位 | 待确认 |
| J7 | 原始执行事实先终态持久化，评分随后以版本化规则生成独立派生记录 | LLM 推断 | 该分层落实 `U12`，避免评分规则影响执行路径或改写原始事实 | 待确认 |

| J9 | 历史存储保留评测定义、原始结果和所有派生结果；保留期、权限及敏感数据策略由部署配置确定 | 待确认项 | 题目要求历史查询，但未给保留期、权限模型和脱敏规则 | 待确认 |

## 验收

### Requirement: 配对版本回归评测

系统 SHALL 在一个不可变评测定义中绑定当前提示词版本、候选提示词版本、任务集快照和执行配置快照，并为每个任务建立双方可追溯的配对执行。

依据：`U1`、`U2`、`J1`

#### Scenario: 创建配对评测

- **GIVEN** 当前版本、候选版本、任务集快照和执行配置均可解析
- **WHEN** 创建一次发布前回归评测
- **THEN** 系统生成唯一评测运行，双方执行项数量与任务标识一致，且每对执行共享 `pair_id`、`task_snapshot_id` 和 `execution_profile_id`
- 验证: auto

#### Scenario: 拒绝不可配对定义

- **GIVEN** 当前版本与候选版本引用不同任务快照或执行配置快照
- **WHEN** 请求启动评测
- **THEN** 系统拒绝进入执行态并返回可定位的定义校验错误
- 验证: auto

### Requirement: 重复运行

系统 SHALL 按配置的重复次数为每个任务和每个提示词版本创建互不覆盖的执行尝试，并保留重复序号用于分轮查询和聚合。

依据：`U9`、`J2`

#### Scenario: 执行多轮评测

- **GIVEN** 有效评测定义的 `repeat_count` 为 3
- **WHEN** 评测执行完成
- **THEN** 每个任务与提示词版本各有 3 条具有唯一尝试标识和重复序号的终态结果，历史结果互不覆盖
- 验证: auto

### Requirement: 执行事实采集

系统 SHALL 为每个执行尝试记录完成终态、工具调用错误、Token 消耗和执行时间，并对不可得指标显式记录缺失原因。

依据：`U3`、`U4`、`U5`、`U6`、`J3`、`J4`、`J5`、`J6`

#### Scenario: 成功执行的完整观测

- **GIVEN** Agent 运行时返回成功终态、Token 用量和工具调用事件
- **WHEN** 执行结果被终态持久化
- **THEN** 结果包含 `succeeded` 状态、结构化工具错误列表、输入/输出/总 Token、开始时间、结束时间和单调时钟耗时
- 验证: auto

#### Scenario: 指标不可用

- **GIVEN** Agent 运行时未提供 Token 用量
- **WHEN** 执行结果被终态持久化
- **THEN** Token 字段标记为不可用并包含原因，系统不生成替代估算值
- 验证: auto

### Requirement: 失败任务隔离

系统 SHALL 将失败限制在对应的独立执行尝试中，并继续调度和收敛其他任务、配对版本及重复轮次。

依据：`U10`、`J10`

#### Scenario: 单任务失败后继续

- **GIVEN** 一个评测包含多个任务及两个提示词版本
- **WHEN** 任一执行尝试发生 Agent 错误或超时
- **THEN** 该尝试进入相应失败终态并保存原因，其余待执行尝试继续运行，评测最终进入可评分状态
- 验证: auto

### Requirement: 评分阶段隔离

系统 SHALL 在所有执行尝试进入终态并持久化原始事实后才运行评分，且执行组件不能读取评分规则，评分结果必须关联使用的规则版本。

依据：`U12`、`J7`

#### Scenario: 执行期不暴露评分规则

- **GIVEN** 评测定义引用一个评分规则版本
- **WHEN** Agent 执行器接收执行请求
- **THEN** 请求只包含提示词、任务与执行配置，且不包含评分规则内容或评分接口能力
- 验证: auto

#### Scenario: 终态结果进入评分

- **GIVEN** 评测中的全部执行尝试均已进入终态并持久化
- **WHEN** 启动评分阶段
- **THEN** 系统基于原始结果生成独立评分记录，每条记录关联 `scoring_rule_version` 且原始结果保持不变
- 验证: auto

### Requirement: 版本对比

系统 SHALL 按任务与重复序号配对当前版本和候选版本的原始指标及评分，生成逐任务差值、汇总差值和可见回归项。

依据：`U7`、`J11`

#### Scenario: 生成配对对比

- **GIVEN** 当前版本和候选版本的执行结果与评分均已就绪
- **WHEN** 运行对比阶段
- **THEN** 系统输出每个 `pair_id` 的完成状态、工具错误、Token、耗时和评分差异，并生成跨任务与重复轮次汇总，单任务回归保持可定位
- 验证: auto

### Requirement: 发布判断

系统 SHALL 使用版本化发布策略消费已完成的对比结果，输出可追溯的发布判断和触发理由；策略缺失或输入不完整时进入人工复核。

依据：`U8`、`J8`

#### Scenario: 策略给出发布判断

- **GIVEN** 对比结果完整且存在有效发布策略版本
- **WHEN** 应用发布策略
- **THEN** 系统输出 `release`、`block` 或 `manual_review`，并记录策略版本、命中条件和依据的对比项
- 验证: auto

#### Scenario: 策略缺失时保守处理

- **GIVEN** 对比结果已生成但发布策略缺失或无法解析
- **WHEN** 请求发布判断
- **THEN** 系统输出 `manual_review` 并记录阻塞原因，不产生自动发布结论
- 验证: auto

### Requirement: 历史结果查询

系统 SHALL 持久化并查询评测定义、原始执行事实、评分、对比和发布判断，返回各层记录的版本与关联关系。

依据：`U11`、`J9`

#### Scenario: 查询历史评测

- **GIVEN** 已存在多次评测和重复运行记录
- **WHEN** 按评测运行标识、提示词版本、任务集快照、时间范围或发布判断查询
- **THEN** 系统返回匹配记录，并可从发布判断追溯到对比、评分、原始执行事实及不可变评测定义
- 验证: auto
