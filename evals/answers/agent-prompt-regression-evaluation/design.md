# 动态模型

## 数据流

1. 评测定义目录解析当前/候选提示词引用、任务集、执行配置、评分规则和发布策略，冻结 `EvaluationDefinition`（`D1`）。
2. 评测编排器按 `task × prompt_version × repeat_index` 展开 `AttemptExecutionRequest`，为同一任务与重复序号的两个版本分配相同 `pair_id`（`D5`）。
3. 隔离执行器只接收提示词、任务和执行配置，调用外部 Agent 运行时；它把运行时事件规范化为唯一 `AttemptResult`，其中包括终态、工具错误、Token、时间和失败原因。评分规则不会进入该数据通道。
4. 结果账本追加保存原始 `AttemptResult`。编排器确认预期尝试全部有终态后，将 `run_id` 和 `scoring_rule_version` 交给评分器。
5. 评分器读取原始结果并生成独立 `ScoreResult`；结果账本保留原始与派生记录的关联及各自版本（`D3`）。
6. 对比与发布判定器按 `pair_id`、`task_id`、`repeat_index` 对齐当前/候选的原始结果和评分，先生成逐对差异，再生成跨任务/重复轮次汇总与回归项。
7. 判定器用 `release_policy_version` 消费完整 `ComparisonResult`，生成 `ReleaseDecision`；结果账本保存判断、理由和全链路引用（`D4`、`D6`）。
8. 历史查询从定义、原始结果、评分、对比或判断任一入口返回记录，并沿全局标识追溯上下游；查询不触发重算或覆盖。

关键数据关系：

- 一个 `EvaluationDefinition` 对应多个 `EvaluationRun`；重复发起同一定义会创建新运行并保留旧运行。
- 一个 `EvaluationRun` 对应 `任务数 × 2 个提示词版本 × repeat_count` 个预期执行尝试。
- 两个提示词版本在相同任务与重复序号下共享一个 `pair_id`；每个尝试拥有唯一 `attempt_id`。
- 每个 `AttemptResult` 可对应多个不同规则版本的 `ScoreResult`；每次评分均追加保存。
- 每个 `ComparisonResult` 明确引用其输入结果集合和评分规则版本；每个 `ReleaseDecision` 明确引用对比结果与发布策略版本。

## 状态流转

### 评测运行状态

状态所有者为评测编排器（`D2`）：

```text
created -> running -> scoring -> comparing -> decided
    |         |          |           |
    +-------> aborted <---+-----------+
```

- `created -> running`：冻结定义校验通过，预期执行矩阵已持久化。
- `running -> scoring`：全部预期尝试均有且只有一个终态；终态可以包含失败或超时。
- `scoring -> comparing`：每个应评分尝试产生评分结果或显式评分错误，评分阶段闭合。
- `comparing -> decided`：对比结果已持久化，发布策略已输出判断；输入或策略异常时判断为 `manual_review`。
- 任一非终态阶段仅在系统级不可恢复错误或显式系统取消时进入 `aborted`。单尝试失败不触发该转换。
- 恢复时，编排器从结果账本读取预期尝试与已存在终态/派生记录，只为尚无终态的尝试按原 `attempt_id` 和幂等键补发缺失工作，禁止重启或重写已有终态的尝试。

### 执行尝试状态

状态所有者为隔离执行器，终态由结果账本唯一约束：

```text
pending -> leased -> running -> succeeded
                     |      -> failed
                     |      -> timed_out
                     +----> cancelled
```

- 租约丢失且未产生终态时，编排器可重新投递同一 `attempt_id`；结果账本只接受第一条合法终态写入，重复写入返回幂等成功或冲突。
- `failed`、`timed_out` 和 `cancelled` 都是可评分、可对比、可查询的终态事实；评分规则决定其评分含义。

### 发布判断状态

- `release`：版本化策略确认候选版本满足发布条件。
- `block`：版本化策略命中阻断条件。
- `manual_review`：策略要求人工复核，或策略缺失、输入不完整、评分/对比异常。

发布判断为记录态，不负责执行发布动作；新策略重判生成新判断记录并保留旧记录。

## 时序

### 正常配对评测

1. 调用方创建 `EvaluationDefinition`；定义目录解析并冻结全部引用。
2. 调用方启动新 `EvaluationRun`；编排器以定义标识作为输入、以运行标识作为幂等边界。
3. 编排器持久化完整预期矩阵后并发投递独立尝试；当前/候选两侧可并发执行，公平性由共享快照与执行配置保证，不依赖固定先后顺序。
4. 每个执行器在租约期限内建立上下文、启动单调计时、调用 Agent、持续采集工具事件和 Token 观测，然后写入唯一终态并释放资源。
5. 单尝试超时或取消会写入不可变终态并终结该尝试，其他尝试继续；需要再次真实执行时创建新运行或新重复序号下的独立 `attempt_id`。基础设施投递失败或 worker 丢失且结果账本尚无该尝试终态时，租约到期才允许按原 `attempt_id` 幂等重投。
6. 编排器观察到全部预期尝试终态后触发评分。评分完成前禁止触发对比；对比持久化前禁止触发发布判断。
7. 对比与发布判断完成后，运行进入 `decided`，历史查询立即可见完整关联链。

### 并发、重试与超时约束

- 同一 `attempt_id` 可因投递至少一次语义被多个工作者观察；执行租约与终态唯一约束保证只有一个有效结果。
- 基础设施投递失败或 worker 丢失且结果账本尚无终态时，重投复用原 `attempt_id`，并保留投递次数与基础设施错误事件。Agent 执行已写入 `failed`、`timed_out` 或 `cancelled` 终态后不再重投该尝试；用户要求再次真实执行时使用新运行或新 `repeat_index` 对应的独立 `attempt_id`。
- 单尝试超时、运行总超时、执行并发上限均来自冻结执行配置。运行总超时到达时，未开始或运行中的尝试分别进入 `cancelled` 或 `timed_out`，随后仍可进入评分。
- 阶段完成事件允许重复投递；评分、对比与判定以 `(run_id, rule_or_policy_version)` 作为幂等键，重复消费不能覆盖既有记录。

## 资源

- **执行槽位**：评测编排器按执行配置中的并发配额申请；隔离执行器从 `leased` 开始持有，写入终态或租约过期时释放。单任务不得无限占用槽位。
- **执行上下文**：隔离执行器为每个 `attempt_id` 创建独立上下文，包含工作目录/会话、工具连接、取消令牌和计时器；终态后清理临时资源，仅保留经脱敏的结果引用。
- **运行时配额**：Token 上限、墙钟超时和工具调用限制属于冻结执行配置并在双方版本间保持一致；耗尽配额形成明确失败终态。
- **持久化容量**：结果账本拥有历史记录和索引；保留期与归档策略待确认（`J9`），清理必须按完整关联链执行并保留审计所需元数据。
- **规则与策略资源**：评分器和判定器按版本只读加载，计算结束后释放缓存；缓存键必须包含版本，避免跨运行误用“最新”内容。

## 故障与恢复

| 失败入口 | 局部处理 | 系统传播 | 恢复/补偿 |
|---|---|---|---|
| 定义引用无法解析或双方快照不一致 | 记录结构化校验错误 | 运行停留在 `created`，不分配执行资源 | 修正引用后创建新定义；不可变旧定义不修改 |
| 单个 Agent 执行报错 | 写入 `failed` 终态及原因 | 其他尝试继续，运行可进入评分 | 评分规则处理失败事实；再次真实运行使用新运行或新重复序号 |
| 单个执行超时或被取消 | 写入不可变的 `timed_out`/`cancelled` 终态并释放资源 | 不触发全局 fail-fast；该终态进入评分 | 不重启该 `attempt_id`；需要再次真实执行时创建新运行或新重复序号下的独立尝试 |
| 工具调用失败 | 追加结构化工具错误事件；Agent 可按运行时策略继续或失败 | 传播为该尝试的观测与可能终态 | 对比保留错误数量和分类差异，历史查询可定位错误摘要 |
| 工作者崩溃或回调丢失 | 租约到期，尝试保持非终态 | 编排器继续处理其他尝试 | 以同 `attempt_id` 幂等重投；首个合法终态胜出，冲突进入审计错误 |
| Token 或时间指标缺失 | 指标标记不可用并保存原因 | 不伪造零值；完整性标记进入评分与对比 | 发布判定默认降级 `manual_review`，待运行时补齐后以新运行复测 |
| 评分规则加载或单项评分失败 | 写入显式评分错误 | 评分阶段闭合后对比标记输入不完整 | 修复规则后以新 `scoring_rule_version` 重评分，保留失败记录 |
| 配对结果缺一侧 | 对比记录缺失侧和原因 | 禁止把缺失值当零；发布判断进入 `manual_review` | 恢复缺失执行结果时重新生成新版本对比与判断 |
| 发布策略缺失或执行失败 | 不产生无依据的自动放行 | 输出 `manual_review` 和阻塞原因 | 补充新策略版本后重判，旧判断保留 |
| 结果账本暂时不可用 | 执行器不得宣告成功提交终态 | 编排器暂停阶段推进，其他可安全执行工作受背压约束 | 按幂等键重试追加；存储恢复后从账本重建运行状态 |

评测不存在兼容迁移或存量数据切换要求，因此本方案不定义迁移阶段；未来接入既有评测数据时需新增迁移模型和重评条件。
