# spec-scope 评分说明（仅评审侧）

每题一分，`writes` 集合与 expected 完全一致才得分。`*` 表示任意不在索引表里的新名字；`问用户` 不看 spec 名。去处取值：加到已有 / 新建 / 只记变更 / 问用户（早期轮次的 append / new / log-only 按同义计分）。

各题考点：
- S01/S02/S03/S10：最直接的 append，确认基本归属。
- S04/S14：调用现有消息类型。message 的"不管什么"写着"什么时候该发"，所以只写调用方。
- S05/S12：表里没有所有者，必须 new；陷阱是塞进 catalog。
- S06：只展示，问"展示的是谁的数据"；陷阱是按页面放进 member。
- S07/S08：工程改动与文案改动只记变更记录。
- S09：等级属于 member，但可借数量上限属于 loan；陷阱是 member。
- S11：注销属于 member，借阅记录只被读取；陷阱是加上 loan。
- S13：一个需求两个所有者，必须两份都写。
- S15：只新增消息类型，不涉及调用方；陷阱是新建 spec 或加上 loan。
- S16：一条场景改了两块数据 → 先拆开，两份都加。
- S17：被调用方多接收参数（输入输出变了）→ message 要加；调用方 loan 行为没变，不列。
- S18：边界表两行重叠 → 问用户，不自己挑。
- S19：spec 写的不是用户要的 → 修改场景（加到已有），不是修 bug 只记变更。
- S20：去掉按钮让用户不能再做某件事 → 是行为，加到已有，不是外观。
