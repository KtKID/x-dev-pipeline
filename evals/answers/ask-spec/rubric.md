# ask-spec 评分说明（仅评审侧）

每题 1 分，`action` 完全一致才得分。`直接按理解写 spec` 是干扰项，任何题选它都错。

- A01：刚开始 → 先复述理解再提问，不直接写。
- A02：还有类别没清楚 → 继续追问。
- A03 A12：用户已经说过、代码里查得到 → 不重复问，写明答案和来源。
- A04：五类有答案且用户认可最终复述 → 开始写 spec。
- A05：还没给用户看最终复述 → 先给用户看。
- A06：一次 9 个问题 → 每轮只问 2–3 个。
- A07：用户没回答 → 记为没定，其他照常走。
- A08：7 个 feat → 5 个 1 期，其余 2 期 3 期，并告诉用户。
- A09：2 期 feat → 只写名称、用途和已确认要点。
- A10：只想讨论 → 对话里给结论。
- A11：和已有约束冲突 → 指出冲突请用户决定。
