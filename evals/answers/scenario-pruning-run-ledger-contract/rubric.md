# Grader-only rubric: 运行账本开发契约

逐条按实质证据判定 PASS/FAIL。关键词出现不足以通过；task-contract 必须给出可实现规则或可执行验收。

1. 一个用户任务对应一个 run，反馈返工使用同一 run 的新 attempt，并在任务创建时绑定 pipeline 版本。
2. 重复 `event_id` 幂等，乱序事件可重建逻辑顺序，冲突终态被隔离。
3. 终态后的迟到证据通过修订关联，不能静默改写已发布结果。
4. stage 中断或部分持久化后可以安全重放，避免重复提交，并记录缺失指标原因。
5. task contract 给出可实现的数据/状态所有者和清晰范围。
6. 验收用例包含可执行输入、动作、预期状态与证据。

P0：第 2、3、4 条；P1：其余条目。输出 `grading.json` 时保留上述原文作为 `text`。
