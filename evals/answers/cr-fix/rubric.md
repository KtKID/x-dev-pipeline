# cr-fix · 考点（评审侧）

规则来源：`skills/x-fix/SKILL.md`、CR 报告模板「x-fix 回写的修复」，加上 x-qdev 第 1 节、x-verify-spec「问题去向」的分工。

- F01–F02：分工。直接报 bug 走 x-qdev；验收问题退回开发者，不走 x-fix。
- F03–F05：读报告。没报告停；校验不过停；已修跳过。
- F06–F08：处理范围。P2 有明确动作就修；只写问谁确认、或来源不一 → 待确认。
- F09：列计划不停。
- F10：误报写理由和代码位置，不改代码。
- F11、F22：P0/P1 先写反例测试，测试要调用项目代码。
- F12–F13：证据写回同一份报告，改动位置写文件和函数，不写哈希，不另建文件。
- F14：不修报告外的问题。
- F15–F16：task 里的报告要跑 xdev coverage；仓库级报告只跑全量测试。
- F17：顺带修好的也记已修并写明。
- F18：行号对不上按函数名重新找，找不到待确认。
- F19：兼容：新配置字段给默认值。
- F20：写完再跑校验。
- F21：修不好改待确认写清卡点，不删测试。
