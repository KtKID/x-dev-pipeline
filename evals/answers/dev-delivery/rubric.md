# dev-delivery 评分说明（仅评审侧）

每题 1 分，`action` 完全一致才得分。`另写一份测试报告` 是干扰项，任何题选它都错。

- D01 D03：覆盖率不到 100%，或改动文件根本不在报告里 → 补测试再跑。D03 的新文件还没有任何测试，答“写测试并登记到用例对应表”也算对。
- D02：本 task 新写的测试红了 → 修好再跑，不改目标。（原有测试红了是 D16。）
- D04：新加排除标记 → 在问题与处置写理由（xdev check 要求）。
- D05：覆盖率跑完代码又改了 → 重跑 coverage。
- D06：需求变了 → 按 change-sync 同步后记新基线。
- D07：用例没对应测试 → 写测试并登记。
- D08：只能人工验证 → 记录放 evidence，结果写“人工通过”。
- D09 D12：Q0 / qdev 没写场景 → check 通过即交付。
- D10 D13：Q1–Q3 / qdev 写了场景 → 交 x-qa-gate。
- D11：qdev 开工 → 先 xdev start。
- D14：真实性检查不通过 → 按回执修测试，重跑 coverage，再派新的子 agent 检查。
- D15：检查后测试又改了 → 覆盖率作废，重跑后旧回执也过期，要重新派子 agent 检查。
- D16：原有测试红了、需求没改这块 → 查是不是自己改坏的，不删不跳过。
