# change-sync 评分说明（仅评审侧）

每题一分，`changes` 集合与 expected 完全一致才得分。没列的项视为"不动"，多列也算错。

各题考点：
- C01：只改场景结果，D 仍成立 → 只改 T、重开行、改测试；D02 不动。
- C02：改 C → 引用 C 的 T 改；D01 仍成立不动；没引用 C1 的 T1 不动。
- C03：新增场景、无新技术约束 → 新增 T、重开同 feat 的已有行，不新增 D、不新增任务行。
- C04：删除场景 → 只为它的 T 退役并新增一条移除后验证；D02 还服务别的场景，不退役。
- C05：只改措辞 → 什么都不动。
- C06：修 bug 且 spec 已写明 → 新增 T 覆盖出 bug 的输入，重开行，spec 和 D 不动。
- C07：场景变化让 D02 不再成立 → D02 改；引用 D02 的所有行都重开；T1、T5 预期没变不改，它们的测试重跑。
