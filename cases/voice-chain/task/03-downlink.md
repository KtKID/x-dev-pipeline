# 考题③：回复语音下发

> 附件清单（随卷必发）：`specs/audio-format.md`、`specs/wire-protocol.md`
> 前置：本题建立在考题①②之上。单发本卷时，快照内已附带一份可用的上传+编排实现。

## 背景

后端拿到 TTS 回复语音后，要把它下发给设备播放。设备端解码能力很弱，只认
`audio-format.md` 规定的播放数据格式。

## 需求

1. AUDIO_END 的 ACK 发出后，后端把 TTS 结果通过 TTS_CHUNK / TTS_END 帧下发给设备
   （帧类型见 `wire-protocol.md`）；
2. 下发的数据必须是设备可直接播放的格式；
3. 设备要能校验收到的数据完整无缺；
4. 下发过程中设备断开连接时，后端不得崩溃，其余会话不受影响。

## 约束

- 只准用 Python 标准库；
- 骨架提供的 `audio.py` 可用可改，**对其正确性负责的是你**；
- 后端启动契约（判分依赖，勿改）：`python3 app.py --port 9000 --config config.json`。

## 交付与自测

- 自测：仿真设备去掉 `--upload-only` 参数即会接收下行帧并把载荷落盘 `out/` 供你检查；
  注意仿真设备只做原样落盘，**不校验协议细节**，细节以规范和判分为准；
- 按你自己的开发流程产出规划/设计/验证文档，判分会按评分表评审。
- 规范未尽事宜：向出题人提问澄清，或在文档中显式记录你的假设。
