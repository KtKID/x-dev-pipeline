# 在编辑器创建 DeepSeek 助手会话

让编辑器在本机启动的 DeepSeek 助手里创建一个空会话，并立即使用返回的会话标识开始对话。

## 本次目标与完成条件

- 本次目标与范围：以原 Eval 的固定版本为基线，只设计创建会话。已保存会话的恢复和后续对话各有独立范围。
- 验证证据：从编辑器的真实入口取得创建结果，核对会话标识可以在当前进程使用，并分别验证参数拒绝、重复创建和失败后重试。
- 完成条件：下列五个场景达到预期，空会话沿用既有的延后保存行为。

## feat01: 创建会话

编辑器可以创建一个空白的本地助手会话。

场景1: 创建成功后立即可用
必要性：原 Eval 要求编辑器能够创建会话，本轮确认了可用与保存的时间边界；缺少时编辑器无法判断收到标识后能否马上使用。
- GIVEN 编辑器已完成初始化，助手进程当前空闲，请求使用合法的启动目录且附加服务和额外目录为空
- WHEN 编辑器创建会话
- THEN 助手返回唯一会话标识，该标识立即对应当前进程可用的空会话，保存时机遵循 C8

场景2: 参数无效时拒绝并可纠正
必要性：原 Eval 约束工作目录、附加服务和额外目录；缺少时无效请求可能越界或占用会话。
- GIVEN 当前进程空闲，请求的工作目录为相对路径或其他目录，或请求包含附加服务或额外目录
- WHEN 编辑器创建会话，再在同一进程提交纠正后的请求
- THEN 首次请求返回错误，纠正后的请求可以创建成功

场景3: 创建进行中拒绝第二次创建
必要性：原 Eval 限制每个进程只承接一个会话；缺少时重叠请求可能同时占用会话。
- GIVEN 首个有效创建请求尚未完成
- WHEN 编辑器提交另一个有效创建请求
- THEN 第二个请求返回错误，首个请求继续并可以返回唯一会话标识

场景4: 已有会话时拒绝第二次创建
必要性：原 Eval 限制每个进程只承接一个会话；缺少时重复创建可能替换已在使用的会话。
- GIVEN 当前进程已有一个成功创建的会话
- WHEN 编辑器再次提交有效创建请求
- THEN 新请求返回错误，原会话标识和会话仍可用

场景5: 底层创建失败后可在原进程重试
必要性：原 Eval [已确认技术设计 D02](../../../pipeline-data/runs/prun-01a1b509-7fed-7d41-947f-f1e16955ad5f-001/artifacts/tech-design-approved.md) 要求创建失败后释放会话位置；缺少时一次临时故障会阻断同一进程内的后续创建。
- GIVEN 请求有效、当前进程空闲，创建时遇到临时故障
- WHEN 编辑器提交创建请求，并在故障解除后于同一进程重试
- THEN 首次请求返回错误，重试可以成功创建并取得可用的会话标识
