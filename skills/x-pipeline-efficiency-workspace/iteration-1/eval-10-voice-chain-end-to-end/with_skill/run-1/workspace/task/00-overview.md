# 全链路考题：语音对话后端

> 本文件只在"全链卷"模式发放，与 01/02/03 三个分段题面同时发。
> 附件清单：`specs/` 全部三份规范。

## 目标

一台语音设备（现阶段用 `fixture/device-sim/` 仿真设备代替真实 ESP32）录音后通过 TCP 上传后端；
后端调用语音转文字（ASR）、大模型（LLM）、文字转语音（TTS）三个服务（现阶段用
`fixture/mock-services/` 本地假服务代替真云服务），把回复语音下发给设备播放。

你要实现的是**后端**（`fixture/backend/`），完整链路：

```
设备 ──HELLO/AUDIO_CHUNK/AUDIO_END──▶ 后端 ──▶ ASR ──▶ LLM ──▶ TTS
设备 ◀──────TTS_CHUNK/TTS_END──────── 后端 ◀──────────────────┘
```

分段需求见 `01-upload.md`、`02-orchestration.md`、`03-downlink.md`，三段需求全部生效。

## 全链路额外要求

1. 多设备并发：多台设备同时对话，会话互不串扰；
2. 一次连接内完成"上传 → 应答 → 下发"全流程；断线续传后同样能走完全流程；
3. 任何一段上游失败，设备侧必须收到 ERROR 帧，不允许无响应挂死。

## 通用约束（各分段题面同样适用）

- 只准用 Python 标准库；
- 端口、超时、重试次数等数值以 `backend/config.json` 与规范文件为真源，代码里禁止另立硬编码；
- 后端启动契约（判分依赖，勿改）：`python3 app.py --port 9000 --config config.json`；
- 按你自己的开发流程产出规划/设计/验证文档，判分会按评分表评审文档质量；
- 规范未尽事宜：向出题人提问澄清，或在文档中显式记录你的假设。
