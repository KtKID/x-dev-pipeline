## 问题详情

### B1：过度压缩删除了隐藏质量所需的判别信息

iteration-6 的四轮限制本身有效，3 次对抗工具调用完成了读取、patch 和验证。质量退化来自同一次改写中删除的判别信息：详细双评分锚点、五个可迁移风险模式、AR-nnn 来源协议和 corpus 门禁。

最短修复路径：

1. 保留四轮执行结构。
2. 把双评分锚点恢复为紧凑表，明确“锁、幂等、崩溃恢复、跨进程并发 → complexity 5”和“本地单用户内部 CLI → importance 1”。
3. 把五个 AR 模式压缩成无证据路径的短模式卡，每项保留 ID、触发条件、被破坏不变量、最小反例和应补 Scenario。
4. v2 来源同时保留可追踪 ID，例如 `adversarial-review (AR-001; pattern:phased-commit)`。
5. 提供轻量 pattern catalog validator，或同步固定隐藏评分器的机械契约。
6. x-spec3 强制复制模板头部前七行，只替换值；eval prompt 显式列出全部任务文件。
