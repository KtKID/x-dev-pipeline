# Iteration 6 对抗审查契约修复报告

> 修复时间：2026-07-23 23:39
> 修复人：Codex (x-fix)

## Bug 描述

iteration-6 的对抗审查优化存在六项契约问题：skill 读取使四轮执行实际增加一轮；standard 状态说明冲突；新来源格式破坏 v1 Spec 兼容；Scenario 总量上限扩大了本轮优化范围；验证失败缺少明确重入入口；测试没有约束真实四轮结构。

## 根因分析

轮次约束只写在 x-adversarial-risk 内部，x-spec3 的 skill 交接读取游离在计数之外。风险版本继续声明为 v1，同时校验器直接替换了 v1 来源语法。新增 Scenario 数量被当作历史总量校验，重复审查会误判。文档与测试聚焦字段校验，缺少调用边界和失败回流契约。

## 修复方案

1. x-spec3 使用一个批量读取调用同时取得 x-adversarial-risk skill、目标 Spec 和通用示例，该调用固定计为第 1 轮。
2. standard 固定写入 `skipped-standard` 与 ARV-1；deep/full 在交接前保持 `pending`。
3. 新模板升级到 `adversarial_risk_version: 2`；校验器按版本分别接受 v1 的 AR-nnn 来源和 v2 的 pattern 来源。
4. 删除 Scenario 历史总量上限，复杂度与重要性只控制单轮候选搜索深度。
5. 聚合验证 issue 可显式触发新的四轮修正调用，x-req3 在门禁失败时传递完整 issue。
6. 增加四轮静态契约测试、v1/v2 来源测试和 iteration-5 真实最终 Spec 回归测试。
