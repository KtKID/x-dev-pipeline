# CR 报告模板

x-cr 按这个格式写，x-fix 按这个格式读和回写。写完运行：

```bash
python3 skills/x-cr/scripts/validate_report.py <报告路径>
```

脚本核对：「范围」「规则表」「问题」三节都在；规则编号合法不重复；结论只用五种；被打破、没法验证、来源不一的规则都连到一个问题；问题表和 `### Bn:` 一一对应；严重度、状态合法；x-fix 回写的「修复」写全了，状态和结果一致，改动位置写文件和函数、不写 commit 哈希。

````markdown
# CR 报告：<一句话说查的是什么>

> 时间：YYYY-MM-DD HH:mm
> 模式：查已知问题 / 检查代码
> 范围：<文件 / 目录 / 模块 / diff / PR>
> spec：<docs/spec/<spec>/spec.md，和 tech-design.md> / 无

## 范围

- 现象或检查目标：<用户看到的错误，或要检查什么>
- 期望：<用户、spec 或接口文档要求的行为>
- 实际：<日志、测试、代码路径或用户描述>
- 看了哪些代码：<主要文件和上下游，一行一个>

## 规则表

| 编号 | 规则 | 来源 | 最小反例 | 结论 | 问题 |
|---|---|---|---|---|---|
| loan:C2 | <规则原文或一句话> | spec.md 关键约束 C2 | GIVEN … WHEN … THEN … | 被打破 | B1 |
| loan:feat03-场景2 | … | spec.md feat03 场景2 | … | 守住了 | - |
| loan:D04 | … | tech-design.md D04 | … | 没走到 | - |
| 新1 | <spec 没写但代码明显该守的规则> | spec 没写；`src/api/auth.py` 的 `login()` | … | 没法验证 | B2 |

编号：spec 里的规则用 `<spec 名>:C2`、`<spec 名>:feat03-场景2`、`<spec 名>:D04`；spec 没写的用 `新1`、`新2`。
结论只用：守住了 / 被打破 / 没法验证 / 没走到 / 来源不一。一条规则连到几个问题时用顿号分隔（B1、B2）。“没走到”在最小反例一栏写依据。

## 问题

| ID | 严重度 | 状态 | 位置 | 一句话 |
|---|---|---|---|---|
| B1 | P0 | 待修 | `src/loan/renew.py` 的 `renew()` 第 12 行 | <问题一句话> |
| B2 | P2 | 待修 | `src/api/auth.py` 的 `login()` | <缺什么证据或规则> |

没有问题时表格只留表头，在下面写一句“未发现问题”。
状态：待修 / 已修 / 误报不修 / 待确认。x-cr 写的都是“待修”，其余由 x-fix 改。

### B1: <问题标题>

- 规则：loan:C2
- 位置：`src/loan/renew.py` 的 `renew()`，第 12–14 行
- 反例：GIVEN … WHEN … THEN …
- 证据：<代码路径（入口 → 校验 → 改状态 → 副作用）、跑过的命令和结果、日志>
- 影响：<谁会遇到、会看到什么、数据或安全后果>
- 怎么改：<修复方向；P2 写补什么证据、问谁确认>

### B2: <问题标题>

…

## 原因排查

<只在“查已知问题”且原因一开始不明时写，否则删掉本节。>

| 可能原因 | 找了什么证据 | 结论 |
|---|---|---|
| <原因 1> | <代码、日志、测试> | 成立 / 排除 / 还不确定 |

## 结论

- 最严重的问题：<B1 一句话>
- spec 要补的规则：<新1 …；没有就写“无”>
````

## x-fix 回写的「修复」

x-fix 修完一条，就在对应 `### Bn:` 的最后加一段，并把问题表里这条的状态改成同样的结果：

```markdown
**修复**

- 结果：已修
- 改动位置：`src/loan/renew.py` 的 `renew()`，第 12–14 行；`src/loan/rules.py` 的 `max_renewals()`
- 反例测试：`tests/test_renew.py::test_renew_after_limit`
- 验证：`pytest` 全量 214 通过；`xdev coverage` 改动行 100%
```

- **已修**：四行都要写。P2 没有可写的反例测试时，“反例测试”写“无，<原因>”。
- **误报不修**：写 `结果：误报不修` 和 `理由：<为什么不是问题，附代码位置>`。
- **待确认**：写 `结果：待确认` 和 `要确认：<要用户定的事>`。
- 改动位置写文件和函数（能写行号就写），不写 commit 哈希。
