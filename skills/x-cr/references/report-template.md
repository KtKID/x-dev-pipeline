# 正确性 CR 报告模板

输出 CR 报告时使用本模板。`不变量覆盖`、`审查结论` 和 `问题详情` 是 x-cr 与 x-fix 的固定交接章节。

写入后运行：

```bash
python3 skills/x-cr/scripts/validate_report.py <CR_REPORT_PATH>
```

```markdown
# Correctness Review 报告

> Report ID: YYYYMMDD-HHmmss
> Schema: x-cr-v2
> Mode: known-issue | module-review
> Scope: task | diff | module | file | PR
> Task ID: <如有>
> Review 日期：YYYY-MM-DD
> 审查范围：<文件 / 模块 / diff / PR>

## 调查对象

| 字段 | 内容 |

| 归属 spec | `<docs/spec/.../spec.md>` / 无 |

## 不变量覆盖

| INV-ID | 来源类型 | 不变量 | 来源 / 依据 | 本次触达路径 | 最小反例 | 结论 | 关联问题 |
|--------|----------|--------|-------------|--------------|----------|------|----------|
| INV-SPEC-01 | spec 声明 | <修改前后持续成立的规则> | `spec.md#影响边界与不变量` / J1 / SC_01 | <入口 → guard → 状态 → 副作用> | <GIVEN/WHEN/THEN> | 保持 / 破坏 / 未验证 / 来源冲突 / 未触达 | B1 / - |
| INV-CAND-01 | 补充候选 | <可能遗漏的规则> | <策略、调用方、测试或仓库证据> | <路径> | <最小反例> | 保持 / 破坏 / 未验证 / 来源冲突 / 未触达 | B2 / - |

### 补充候选与 spec 关系

| INV-ID | 关系 | 证据 | 后续 |
|--------|------|------|------|
| INV-CAND-01 | 已被 spec 覆盖 / spec 缺口 / 待确认 / 来源冲突 | <证据> | 合并验证 / 补 spec / 确认权威来源 |

结论规则：

- `破坏` 映射一个稳定 Bn。
- `未验证` 和 `来源冲突` 映射 Bn 或明确最短补证动作。
- `未触达` 写明 diff/调用链未经过执行路径的证据。
```
