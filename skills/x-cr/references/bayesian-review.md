# 贝叶斯根因调查法

本文件定义 x-cr 如何在不变量和最小反例已经明确后，更新候选根因的置信度。目标是把直觉判断转成可追踪的证据链。

## 公式

```text
P(H | E) = P(E | H) * P(H) / P(E)
```

| 符号 | 含义 |
|------|------|
| H | 候选根因，例如“remember rule 把子命令保存成根命令” |
| E | 日志、测试失败、代码路径、diff、spec、不变量或调用链证据 |
| P(H) | 看到新证据前的先验 |
| P(E \| H) | H 成立时观察到当前证据的可能性 |
| P(H \| E) | 看到证据后 H 成立的置信度 |

x-cr 使用定性等级：

| 等级 | 含义 |
|------|------|
| 低 | 证据明显削弱该根因 |
| 中 | 有支持证据，同时存在关键缺口或反证 |
| 高 | 多条独立证据支持，反证检查未推翻 |
| 已确认 | 有复现、明确调用链、直接 spec/不变量冲突或确定失败路径 |

置信度表达证据强度，P0/P1/P2 表达影响程度。

## 两种入口

### 已知问题入口

1. 抽取用户现象、期望行为和实际行为。
2. 定位归属 spec 及相关不变量。
3. 把用户现象作为 E0，把最小复现映射到受影响不变量。
4. 建立候选根因 H1-Hn。
5. 逐步读取日志、代码、测试、配置、spec 和调用链，更新置信度。
6. 对最高置信候选执行反证检查。

### 模块 review 入口

1. 读取 spec 的相关不变量和 Scenarios。
2. 建立模块模型并登记遗漏候选不变量。
3. 为每个受影响不变量构造最小反例。
4. 围绕可能的破坏路径建立候选根因。
5. 读取入口、guard、状态所有者、副作用和测试断言。
6. 输出不变量结论、根因置信度和覆盖声明。

## 候选生成

候选围绕“哪条规则会被怎样击穿”生成：

- spec/实现：实现与目标、不变量或 Scenario 冲突。
- 输入：空值、非法类型、超大输入、路径穿越、特殊字符。
- 信任：客户端声明被直接当成身份、角色、租户、所有权或授权结果。
- 权限：批准范围被规范化、匹配、缓存或持久化逻辑扩大。
- 状态：未初始化、部分初始化、终态复用、跨请求污染。
- 依赖：超时、空响应、非法数据、schema 漂移、部分失败。
- 并发：重复提交、重试、乱序、缓存过期、幂等或锁规则破坏。
- 资源：成功、失败、取消和超时路径中的释放与提交顺序。
- 测试：happy path-only、自我 mock、用业务逻辑计算期望值、fixture 过拟合。

这些类别用于启发候选，调查继续寻找同类原因。通常先保留 3-6 个高解释力候选；模块范围扩大或出现新证据时继续增加。覆盖表决定调查完成。

每个候选记录：

- 关联 INV-ID。
- 触发条件。
- 预期失败路径。
- 可能影响。
- 定性先验。
- 最短取证动作。

## 证据分类

支持证据：

- 用户现象与候选路径一致。
- 最小反例可复现不变量破坏。
- 日志、栈和测试失败指向同一函数或状态。
- diff 删除 guard、扩大范围、改变状态转换或数据映射。
- spec 要求 A，代码行为为 B。
- 调用链可进入风险状态并到达副作用。

削弱证据：

- 上游保证输入条件且真实入口始终经过该保证。
- schema 或运行时校验覆盖风险输入。
- 服务端从可信状态重新推导身份与权限。
- 测试覆盖真实路径并独立断言不变量结果。
- 配置默认值、迁移或错误处理已覆盖该状态。
- 权威 spec 明确允许当前行为。

中性证据：

- 只说明文件被改动。
- 只说明函数存在。
- 只说明测试通过，且测试覆盖与断言强度仍未确认。
- 只说明调用方当前没有使用风险输入。

## 反证检查

高置信候选进入结论前检查：

1. 是否存在更上游的真实 guard。
2. 是否存在服务端二次校验或状态重新推导。
3. 是否存在 schema、类型或配置约束。
4. 是否存在覆盖真实路径的负向测试。
5. 是否存在错误处理、事务或回滚兜底。
6. 是否存在已确认、版本化的权威契约变更。

反证需要可定位证据。口头假设保持为证据缺口。

## 根因分类

| 分类 | 使用条件 |
|------|----------|
| 原始 spec 不一致 | 当前行为与明确 spec 或已声明不变量冲突 |
| 实现过程偏移 | spec 清楚，实现漏做、做偏、回归或半成品 |
| spec 缺口 | 真实规则缺少关键边界、状态、错误路径或验收标准 |
| 环境/数据问题 | 代码契约成立，配置、环境、数据形状或迁移状态异常 |
| 证据不足 | 缺少复现、日志、调用链、spec 或关键文件 |

## 判定规则

- `已确认` 和 `高` 置信度进入问题结论。
- `中` 置信度保留严重度判断，同时明确需讨论或最短补证路径。
- `低` 置信度写入已排除假设。
- 测试通过作为辅助证据，检查测试是否覆盖真实路径并能击穿错误实现。
- 不变量的影响决定严重度，根因证据决定置信度。
