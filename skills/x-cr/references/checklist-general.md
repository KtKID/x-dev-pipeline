# 正确性检查清单

x-cr 只检查会影响软件正确性的事项。严重度表达影响，置信度表达证据强度；两者分别记录。

## 不变量覆盖

每个模块 review 先完成：

- 从归属 spec 的“影响边界与不变量”提取本次相关规则。
- 检查目标、上游、下游和相关模块。
- 从状态/权限所有者、入口、调用方、副作用和失败路径寻找遗漏候选。
- 为每个受影响不变量构造最小反例并追踪真实执行路径。
- 给出 `保持 / 破坏 / 未验证 / 来源冲突 / 未触达`。
- 把补充候选归类为 `已被 spec 覆盖 / spec 缺口 / 待确认 / 来源冲突`。

每个“破坏”结论关联一个 Bn 问题；每个“未验证”或“来源冲突”结论给出最短补证动作。

## P0：阻断性正确性错误

P0 表示事故影响触达安全、数据或核心系统规则：

- 授权能力扩大、鉴权绕过或服务端信任客户端伪造身份/角色/租户/所有权。
- 用户、租户、会话、线程、workspace、cwd 或设备隔离被突破。
- 数据破坏、丢失、不可逆错误写入或恢复边界失效。
- 核心不变量被破坏，核心路径无法完成。
- 失败被报告为成功并产生关键副作用。
- 并发、幂等、事务或持久化顺序破坏核心状态。

P0 必须包含：

- 关联 INV-ID。
- 触发条件和最小反例。
- 从入口到副作用的可达路径。
- spec/权威契约与当前行为证据。
- 反证检查结果。
- 独立置信度。

## P1：生产正确性风险

P1 表示存在可达的用户可见错误，影响可恢复或范围受限：

- 边界输入导致异常、空结果或错误分支。
- 部分初始化、重复调用、终态复用或资源生命周期导致状态错误。
- 错误处理吞掉失败，使调用方得到错误结果。
- 缓存、配置、数据形状或迁移变化改变局部行为。
- 并发、重试和幂等路径产生受限范围的重复或丢失。
- 公开 API、CLI、事件或配置契约发生可见回归。

P1 必须包含：

- 关联 INV-ID 或明确说明该问题属于 spec 缺口。
- 受影响的用户或系统路径。
- 当前证据和反证检查。
- 提升置信度所需的最短证据。

## P2：正确性证据或契约缺口

P2 表示当前缺少可达破坏路径，同时缺口会影响后续判断：

- spec 缺少关键不变量、边界、状态、错误路径或验收标准。
- 追加候选不变量缺少权威来源确认。
- spec、策略、调用方或用户约束存在来源冲突。
- 测试没有断言核心契约或无法击穿错误实现。
- 日志缺少定位信息，无法区分候选根因。
- 模块入口、状态所有者、权限所有者或调用方契约缺少证据。
- 真实运行环境或依赖行为仍未验证。

P2 输出给出：

- 需要确认的 spec 或策略。
- 需要补的测试或日志。
- 需要读取或运行的最短命令。
- 缺口关闭后应重新判断的 INV-ID。

## 置信度

| 等级 | 证据要求 |
|------|----------|
| 低 | 证据明显削弱，写入已排除假设 |
| 中 | 有支持证据，同时存在关键缺口或反证 |
| 高 | 多条独立证据支持，反证检查未推翻 |
| 已确认 | 有复现、明确调用链、直接 spec/不变量冲突或确定失败路径 |

严重度保持基于影响。低或中置信度的高影响候选保留影响说明，并进入最短补证路径。

## Spec 对照

每个 P0/P1 问题和每个补充候选都给出 spec 关系：

| 分类 | 判定 |
|------|------|
| 原始 spec 不一致 | 代码行为与明确 spec/不变量冲突 |
| 实现过程偏移 | spec 清楚，实现漏做、做偏或回归 |
| spec 缺口 | spec 缺少真实边界或不变量 |
| 环境/数据问题 | 代码契约成立，环境、配置或数据异常 |
| 证据不足 | 关键证据缺失 |
| 符合 spec | 当前证据证明规则保持 |

## 退出范围

以下内容归属相邻 skill：

- 命名、格式、排版和纯代码风格。
- 缺少可达错误路径的结构与抽象建议。
- 纯性能优化建议；超时、资源耗尽或用户可见失败继续归 x-cr。
