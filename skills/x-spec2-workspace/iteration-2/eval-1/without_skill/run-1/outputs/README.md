# StackChan ESP32-S3 语音收发模块：系统需求包

## 1. 文档定位

本文档包定义可直接交给需求细化阶段的系统边界、行为契约、接口、质量属性和验收口径。范围停留在系统方案层，不包含开发任务拆解、实现代码、芯片选型结论或供应商绑定。

配套文档：

- `architecture.md`：系统分层、组件职责、关键链路与状态机。
- `protocol.md`：会话、消息、音频帧、取消与恢复契约。
- `quality-and-acceptance.md`：性能、可靠性、可观测性、安全与场景验收。
- `assumptions-and-open-questions.md`：方案假设、待确认项和决策门槛。

## 2. 目标与范围

### 2.1 系统目标

在基于 StackChan 的 ESP32-S3 开发板与服务端之间建立低延迟、可打断、可观测、可恢复的语音闭环：

1. 用户通过本地唤醒词进入收音。
2. 设备持续采集、分帧并上传语音。
3. 服务端流式接收音频，由 ASR 生成最终文本。
4. 响应文本生成组件根据识别文本产出待播报文本。
5. TTS 组件边合成边下发音频，设备以小缓冲流式播放。
6. 用户在播放期间发起新一轮语音时，设备立即停播并开始新一轮收音；服务端异步取消旧响应。

### 2.2 系统边界

系统内包含：

- ESP32-S3 上的唤醒、采集、上行、播放、打断、连接恢复和本地遥测。
- 服务端连接接入、会话协调、ASR、响应文本生成、TTS、取消传播和端到端观测。
- 设备与服务端之间的认证、全双工传输协议和恢复协议。

系统外依赖：

- StackChan 机械结构、表情和动作系统；本方案只提供可供其消费的会话状态事件。
- Wi-Fi 网络、时间同步服务、ASR/TTS 供应商及响应文本生成服务。
- 设备配网、量产烧录、固件升级和云端账号后台。

### 2.3 本期非目标

- 连续多说话人分离、声纹身份识别与会议转写。
- 离线 ASR、离线 TTS 和长期离线对话。
- 服务端业务问答内容、人格策略和动作编排细节。
- 保存、检索或训练用户原始语音。

## 3. 术语与标识

| 名称 | 含义 |
|---|---|
| 连接 `connection_id` | 一次底层网络连接；重连后变化 |
| 会话 `session_id` | 一段设备在线交互上下文；短时重连时保持 |
| 话轮 `utterance_id` | 从一次成功触发 listen 到 ASR 终止的唯一标识 |
| 响应 `response_id` | 针对最终识别文本生成的一次响应及 TTS 流 |
| 代际 `generation` | 设备当前接受的播放代号；打断时单调递增 |
| 追踪 `trace_id` | 贯穿唤醒、上传、ASR、响应生成、TTS 和播放的关联标识 |

所有标识在其作用域内唯一。服务端和设备均以 `session_id + utterance_id`、`session_id + response_id` 作为幂等键。

## 4. 核心用户场景

### 4.1 正常话轮

1. 设备在线且处于 `READY`，唤醒检测器持续低功耗运行。
2. 唤醒词命中后，设备创建 `utterance_id` 和 `trace_id`，进入 `LISTENING`，立即采集并上传带序号音频帧。
3. 本地端点检测结束后，设备发送 `audio_end`；服务端完成 ASR 并发出唯一的最终文本事件。
4. 响应文本生成组件产出播报文本；TTS 首帧就绪后，服务端发送 `tts_start` 和连续音频帧。
5. 设备达到最小起播水位后进入 `PLAYING`，播放完毕后回到 `READY`。

### 4.2 播放中打断

1. 播放期间，本地唤醒词、经过回声抑制的语音触发或物理按键产生打断事件。
2. 设备在本地立即静音并停止解码，递增 `generation`，清空旧响应缓冲区。
3. 设备发送幂等 `cancel`，同时创建新话轮并进入 `LISTENING`，无需等待服务端确认。
4. 服务端停止旧响应生成/TTS，发送 `cancel_ack`；在途旧音频因 `response_id/generation` 不匹配被设备丢弃。

### 4.3 网络或服务波动

1. 连接管理器发现心跳、写入或读取失败后进入 `RECOVERING`，按抖动退避重连。
2. 短暂上行中断时，设备保留有界的未确认音频帧；恢复握手后从服务端确认序号之后重放。
3. 无法完整恢复当前话轮时，系统显式终止该话轮，给出本地可理解反馈，并回到可再次唤醒的 `READY`。
4. 播放流无法续传时，设备终止旧响应并回到 `READY`；任何旧帧均无法跨代继续播放。

## 5. 功能需求

优先级采用 `P0`（上线必需）、`P1`（稳定运行必需）、`P2`（后续增强）。

### 5.1 设备侧

| ID | 优先级 | 需求 |
|---|---|---|
| DEV-001 | P0 | 设备在 `READY` 和 `PLAYING` 状态持续运行唤醒检测，并在命中时生成带时间戳的本地事件。 |
| DEV-002 | P0 | listen 启动后立即采集单声道音频，以固定时长帧输出，序号严格递增。 |
| DEV-003 | P0 | 设备执行本地端点检测，并对最长收音时长设置硬上限；结束原因随 `audio_end` 上报。 |
| DEV-004 | P0 | 设备通过一条已认证的全双工长连接并发收发控制消息和音频流。 |
| DEV-005 | P0 | 设备接收分片 TTS 音频，以有界抖动缓冲起播，持续报告已接收和已播放位置。 |
| DEV-006 | P0 | 打断触发后先完成本地停播和旧缓冲清理，再异步通知服务端；本地动作不依赖网络往返。 |
| DEV-007 | P0 | 每个播放帧均按 `response_id` 和 `generation` 校验，过期帧不得进入解码器。 |
| DEV-008 | P1 | 设备保留有界的未确认上行帧，在短时断线后按确认序号重放；缓冲溢出时显式终止话轮。 |
| DEV-009 | P1 | 设备限制采集、发送、接收、解码各队列容量，暴露水位并定义溢出行为。 |
| DEV-010 | P1 | 设备维护结构化事件环形缓冲，网络恢复后批量补传；原始音频默认不进入遥测。 |
| DEV-011 | P1 | 状态变化以稳定事件接口提供给 StackChan 表情/动作层，语音链路不等待动画完成。 |
| DEV-012 | P1 | 连续失败达到阈值后进入可诊断的降级状态，仍保留配网、重连和本地状态反馈能力。 |

### 5.2 服务端

| ID | 优先级 | 需求 |
|---|---|---|
| SRV-001 | P0 | 接入层认证设备，协商协议版本和音频能力，并建立 `session_id` 到连接的唯一活动绑定。 |
| SRV-002 | P0 | 会话协调器校验消息状态、标识和序号，将连续音频流提交给 ASR 适配器。 |
| SRV-003 | P0 | 每个话轮只发布一次最终 ASR 文本；重复或延迟回调通过幂等键消解。 |
| SRV-004 | P0 | 最终文本进入响应文本生成组件，结果以 `response_id` 关联到原话轮。 |
| SRV-005 | P0 | TTS 适配器支持首块就绪即下发、连续分片和明确结束事件。 |
| SRV-006 | P0 | `cancel` 从接入层传播到响应文本生成和 TTS；重复取消返回同一终态。 |
| SRV-007 | P0 | 服务端停止向已取消、已替换或已断开的播放代际继续派发音频。 |
| SRV-008 | P1 | 服务端维护短期可恢复会话状态和上行确认点；重连握手返回可恢复范围。 |
| SRV-009 | P1 | ASR、响应生成和 TTS 均设置独立超时、并发隔离和熔断策略，故障映射为稳定错误码。 |
| SRV-010 | P1 | 接入层对设备、会话和租户执行并发、带宽、消息大小和速率限制。 |
| SRV-011 | P1 | 所有关键阶段产生统一追踪事件和指标，并携带端到端关联标识。 |
| SRV-012 | P2 | ASR/TTS 适配器允许按能力与健康状态切换供应商，切换过程保持上层协议稳定。 |

### 5.3 端到端行为

| ID | 优先级 | 需求 |
|---|---|---|
| E2E-001 | P0 | 一次话轮在任意时刻只有一个有效后继状态和一个可播放响应代际。 |
| E2E-002 | P0 | 打断优先级高于播放完成、TTS 到帧和连接恢复；并发事件按设备本地打断时间定序。 |
| E2E-003 | P0 | 重试不得造成重复 ASR 最终结果、重复响应生成或旧音频复播。 |
| E2E-004 | P1 | 每个终止的话轮和响应均有明确终态：完成、取消、超时、不可恢复断线或内部失败。 |
| E2E-005 | P1 | 设备时间不可用或发生漂移时，端到端顺序仍由单调时钟、序号和服务端接收时间确定。 |

## 6. 状态与一致性约束

设备主状态为：

`BOOTING → CONNECTING → READY → LISTENING → WAITING_RESPONSE → PLAYING → READY`

`RECOVERING` 可从任何联网状态进入；恢复成功后根据恢复结果返回原状态或 `READY`。`DEGRADED` 表示连续失败后的可诊断降级状态。

必须成立的不变量：

- `PLAYING` 时只有一个 `response_id/generation` 可写入解码器。
- 新话轮创建后，前一响应立即失去本地播放资格。
- `audio_end` 之后的同话轮音频帧被拒绝并记录协议事件。
- 最终 ASR、TTS 结束和话轮终态均为幂等事件。
- 连接变化不改变业务标识；会话过期或设备重启会创建新 `session_id`。
- 所有队列有容量上限，任何溢出都有确定的丢弃、取消或重连策略。

## 7. 需求交付门槛

进入详细需求阶段前，应形成以下已确认输入：

- 目标 StackChan 硬件版本、麦克风/扬声器拓扑、可用 PSRAM 与同时采播能力。
- 上行和下行音频格式、采样率、帧长、最大码率及服务端兼容矩阵。
- 响应文本生成组件的业务语义、超时和内容安全责任边界。
- 参考网络条件、并发规模、数据驻留区域及可接受的日志保留周期。
- `quality-and-acceptance.md` 中 P0 指标和故障场景的签字口径。
