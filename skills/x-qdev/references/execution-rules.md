# x-qdev 执行规则

## 状态规范

| 符号 | 状态 | 说明 |
|------|------|------|
| ⏳ | 未开始 | 等待处理 |
| ▶️ | 进行中 | 正在实现 |
| 🟡 | 待验证 | 实现完成，等待真实验证 |
| 🔴 | 验证失败 | 证据显示存在问题，等待修复 |
| 🟢 | 证据通过 | 当前验证通过，等待风险路线收尾 |
| ✅ | 已完成 | DoD 证据闭环，所需审查路线已通过 |
| ↗️ | 已升级 | qdev 停止，完整流程 task 接管完成状态 |

状态流转：

```text
⏳ → ▶️ → 🟡 → 🟢 → ✅
             ↓
             🔴 → 修复 → 🟡
⏳/▶️/🟡/🟢 → ↗️ 已升级
```

## 完成条件

任务进入 ✅ 需要同时满足：

1. 代码或文档实现完成。
2. README 中每条 DoD 都有最终证据。
3. `dev-report.md` 记录实际 diff 和真实验证结果。
4. Q0/Q1 已完成主 agent 证据检查；Q2 已取得综合 reviewer pass。
5. 当前任务没有阻塞项。

Q3 使用 `↗️ 已升级` 终态。原 qdev task 保存交接证据，新 full task 负责最终 ✅。

## 更新时机

- 开始实现时更新为 ▶️。
- 实现完成时更新为 🟡。
- 验证失败时更新为 🔴，并记录失败证据。
- 验证通过时更新为 🟢，并填写 DoD 证据矩阵。
- 风险路线收尾完成时更新为 ✅。
- Q3 交接路径建立后更新为 ↗️。

## 风险变化

- Q0 出现行为变化时重新判断为 Q1 或更高。
- 影响 DoD、公开行为或数据语义的歧义在开发前交给用户确认。
- Q1 出现已明示的低影响实现假设、核心函数或重要失败路径时重新判断为 Q2。
- 出现鉴权、不可逆数据、公开协议/schema、并发状态或跨模块架构时升级 Q3。
- 每次风险等级变化都更新 README 和 changelog。

## Changelog 记录范围

记录任务开始/完成、风险变化、验证失败、关键决策、综合 reviewer 结论和流程升级。普通状态切换直接更新 README，避免形成流水账。
