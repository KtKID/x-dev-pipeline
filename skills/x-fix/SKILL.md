# x-fix · 按 CR 报告修复

只修 x-cr 报告里的问题。修完的证据写回同一份报告，不另建修复报告。

## 流程

```text
1 读报告 → 2 列计划 → 3 逐条修 → 4 跑测试 → 5 回写报告 → 6 回执
```

### 1. 读报告

- 用户给了路径就用；没给就找当前 task 的 `reports/cr/`（qdev 是 `task-<name>-evidence/cr/`）下最新一份，再找仓库根目录 `reports/cr/` 下最新一份。
- 找不到：停下，告诉用户先跑 x-cr。
- 先跑校验，不通过就停下，把校验错误交给用户（报告要回 x-cr 改）：

  ```bash
  python3 skills/x-cr/scripts/validate_report.py <报告路径>
  ```

- 问题表里状态已经是“已修”“误报不修”的跳过；“待确认”的看用户有没有给出答案，给了就按答案修，没给就保持原样。

### 2. 列计划

给用户列一次计划，然后接着往下做，不等确认：

- P0、P1：修。
- P2：报告里“怎么改”写了明确动作（补哪条测试、补哪段日志、改哪处代码）就修；只写“问谁确认”的，状态改“待确认”。
- 报告规则结论是“来源不一”的：不修，状态改“待确认”，列出要用户定的事。

```text
📋 修复计划 · <报告路径>
修：B1 (P0) `src/loan/renew.py` 的 renew() — 续借次数没限制
修：B3 (P2) 补 tests/test_auth.py 的越权用例
待确认：B2 — spec C2 和用户说法不一，要定按哪个
```

### 3. 逐条修

对每一条：

1. 打开报告写的位置。行号对不上就按函数名、关键词重新找；找不到就把这条改“待确认”，写清找不到的原因，接着修下一条。
2. 先判断是不是真问题。不是：不改代码，状态改“误报不修”，写理由和证明它没问题的代码位置。
3. 是真问题：只改必要的代码，不顺手重构、不改无关风格。改法和报告建议不同，在修复段里一句话说明。
4. 每个 P0、P1 先写一条能复跑的反例测试：修之前它失败，修之后通过。测试要调用项目代码，不重新实现一遍逻辑，不 mock 掉被测对象，不写恒真断言。
5. 修 Bn 时顺带修好了 Bm：Bm 也写“已修”，修复段写“随 Bn 一起修好”，反例测试写能证明它的那条。

修复动到配置、命令行、公开接口、协议或数据格式时，原来能用的输入要继续能用：新配置字段给默认值；确实要不兼容的，先问用户。

### 4. 跑测试

- 跑项目全量测试，必须全绿。
- 在 task 里修的（报告在常规 task 的 `reports/cr/` 或 qdev task 的 `task-<name>-evidence/cr/`），再跑 `xdev coverage`，改动行覆盖率 100%，做法见 [证据约定](../x-dev/references/test-reporting.md)。
- 不在 task 里的（报告在仓库根目录 `reports/cr/`）：只跑项目全量测试，不跑 `xdev coverage`。
- 测试没全绿：接着修，修不好就把那条改“待确认”，写清卡在哪。

### 5. 回写报告

每修完一条，在报告对应 `### Bn:` 的最后加「修复」段，同时把问题表里这条的状态改成同样的结果。格式见 [CR 报告模板](../x-cr/references/report-template.md#x-fix-回写的修复)：

```markdown
**修复**

- 结果：已修
- 改动位置：`src/loan/renew.py` 的 `renew()`，第 12–14 行
- 反例测试：`tests/test_renew.py::test_renew_after_limit`
- 验证：`pytest` 全量 214 通过；`xdev coverage` 改动行 100%
```

- 改动位置写文件和函数，能写行号就写；不写 commit 哈希。
- 误报不修写“理由”，待确认写“要确认”。
- 全部写完再跑一次校验脚本，通过才算完成。

### 6. 回执

```text
✅ 修复完成 · <报告路径>
已修 a 条 · 误报不修 b 条 · 待确认 c 条
全量测试：<命令> <结果>；改动行覆盖率：<100% / 不在 task 里，未跑>
待确认：B2 — <要用户定的事>
可以提交：git add <改动的文件> && git commit -m "fix: <一句话>"
```

## 不做的事

- 不修报告外的问题。修的时候发现新问题，写进回执，建议再跑一次 x-cr。
- 不改报告里 x-cr 写的规则表、反例和证据，只加「修复」段、改状态。
- 不为了让测试过去删用例、降低断言或加没有理由的覆盖率排除标记。
