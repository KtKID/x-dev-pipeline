# L3 文档对代码

核对 x-feat-doc 写的模块说明（模块目录里的 `readme.md` / `README.md`）还对不对得上代码。**能机械核对的交给脚本，AI 只核对描述行为的句子。**

## 脚本做什么（`audit.py l3`）

对范围内每份 readme：

- **文件链接**：每个指向项目内文件的链接，文件还在不在；带 `#章节` 的，章节标题还在不在。
- **函数名**：反引号里写成 `名字()` 的，在模块代码里找得到定义吗。
- **文件名**：反引号里写的路径，文件还在不在。
- **配置项和默认值**：readme 里写成 `键 = 值` 或 “`键` 默认 `值`” 的，代码里这个键的默认值是不是同一个。

每一条记一行结果：对得上 / 找不到 / 值不一样。找不到和值不一样的成为问题。

## 子 agent 做什么

只对“readme 或它描述的代码，在上次巡检以来变过”的模块做。读 readme 和模块代码，逐项核对：

| 检查项 | 看什么 |
|---|---|
| 功能描述对得上 | readme 说模块能做的事，代码现在是不是这样做的 |
| 使用方式能用 | 写的入口、命令、步骤，照着做能不能成功（能跑就真跑） |
| 关键函数说明对得上 | 每个关键函数的用途、输入、结果，和函数现在的代码是否一致 |
| spec 索引还对 | 列出的 spec 还在、说的关系还成立 |

写错的成为问题，按 severity.md 定级；修法是用 x-feat-doc 重写对应章节。
