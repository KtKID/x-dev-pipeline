# L6 性能

一次看一个模块，找“访问量一大就会慢、会卡、会占满资源”的写法。只报能指出具体代码、说得清在什么情况下会慢的问题；数据量很小、调用很少的地方不报。

| 检查项 | 看什么 | 有问题的例子 |
|---|---|---|
| 循环里没有查库或调接口 | 一次请求里是不是在循环中一条条查数据库、调远程接口、读文件 | 列出 100 个读者，每个读者再查一次借阅表（N+1） |
| 没有重复计算 | 同样的结果是不是每次都重算，尤其在循环里 | 循环里每次都重新解析同一份配置 |
| 数据结构用得合适 | 大量查找用了列表、在大列表上反复 `in` | 每来一个请求就在 10 万条的列表里线性找 |
| 没有不必要的等待 | 异步代码里有没有同步阻塞；本可以一起做的事是不是一个个等 | async 函数里用 `time.sleep`、同步 HTTP 客户端 |
| 资源用完会释放 | 连接、文件、锁、后台任务在成功和失败时都关掉了吗 | 打开文件不关；出错时连接没还回连接池 |

每个问题写清楚“在什么情况下会慢、大概会慢成什么样”，比如“读者一多，打开列表页要查几百次数据库，页面会卡好几秒”。
