# L4 模块审查

一次只看一个模块的内部，回答“这个模块写得好不好维护”。**正确性（会不会算错）归 x-cr；lint 能管的规范归 L1；没人用的代码归 L2；跨模块的结构归 L5。** 这些这里都不查。

读这个模块的代码和它的测试，按下面的检查项逐项给结论：

| 检查项 | 看什么 | 有问题的例子 |
|---|---|---|
| 职责单一 | 模块和它的主要函数是不是只管一件事 | 续借函数里顺带发邮件、写日志文件、算罚款 |
| 对外接口说清楚 | 别的模块调用它时，输入什么、返回什么、会不会改别的状态，看签名和说明就知道吗 | 到处传裸 dict；返回值有时是列表有时是 None |
| 错误情况处理清楚 | 出错时调用方知道会发生什么吗；有没有把错误吞掉、把失败当成功 | `except: pass`；失败时返回空列表，调用方以为“没有数据” |
| 测试真在测 | 测试是不是调用了模块的真实代码、检查了真实结果 | 只断言 mock 被调用；把被测函数整个 mock 掉；断言恒为真 |

“测试真在测”只看这个模块的测试写得对不对，不跑覆盖率。
